## 一、这套配置是什么

凯凯 AI 影视制作团队的 Claude Code multi-agent 配置，面向从零到「提示词包」的完整 AI 视频制作流程。用户拿提示词包去 Seedance / 即梦 / Nano Banana 等视频生成工具生成素材，再后期剪辑成片。

6 个创作 agent：编剧 / 导演 / 服化道 / 音乐总监 / 分镜师 / 审核专员。制片人（用户当前 session 的 Claude Code 主进程）调度。

**主场定位**：精品微电影 + MV（全装档）。短剧 / 漫剧 / UGC 为延展方向（轻装档）。

## 二、用户核心诉求（访谈提炼）

### 2.1 不可动的设计决策

以下是用户明确说「不想再改」的核心设计，任何升级都必须保留：

| 决策 | 理由 |
|---|---|
| 6 agent 分工架构 | 职能清晰，下游只执行上游决策，不越权 |
| `max_seconds` config 驱动 | 换模型只改配置，不改任何提示词文件 |
| 分镜两步制（镜头表 → ★表确认 → 编译） | 「想戏」和「翻译」分开，改表是几行字，改提示词是重来 |
| 条头三行 + 围栏四块格式 | 围栏第一个字就是模型读的，用户复制即生成，零替换 |
| 音乐隔离（不进提示词，后期整条铺） | 避免模型自作主张塞配乐；例外：`content_type=mv` |
| 画幅一次声明（只在 video-prompts.md 顶部） | 消除画幅传染问题 |
| 故事板与控制图均为手动模式 | 用户没明确要就不做 |
| 参考图默认单张（`grid_mode=single`） | 九宫格字样进提示词会触发生图工具出宫格 |
| reviewer 独立（每次空白上下文，查病制） | 保证客观；不评分，只查五类病 |
| 175 位导演色卡库（三文件） | 用户内容的电影感来源 |

### 2.2 内容与美学偏好

以下来自用户在 v13 升级中明确写下的「用户补充要求」（原始来源：CHANGELOG.md v13 段）：

- **故事板改手动模式**：带标注/曲线/表格的华丽故事板丢进视频模型会被当画面内容渲染，错漏百出
- **定镜原则**：`max_seconds` 是上限不是目标，每镜按剧情实际定长
- **能合并就合并**：相邻同空间同时间流有因果的剧情合并为一 Cut，剧情原生在同一段视频里比后期拼碎片质量高
- **B 轨优先**：镜头N + 配重语言，不写秒数；A 轨时间戳只给一镜到底的因果段落
- **故事优先**：用户多次强调「AI 让执行成本趋近于零，省出来的时间用在构思分镜和故事上」

### 2.3 工作流习惯

- 从以下多种素材起笔都很常见：选题方向、创意碎片、故事标题、故事梗概、多章节小说节选、大纲草稿。均放 `input/选题/`，编剧按内容深度自行判断
- 用户会把生成好的 PNG 存进 `assets/visual/images/`，文件名照 `reference-index.md`，然后分镜师的上传清单按名字引用
- 用户希望 episode-master 里的资产清单直接显示文件名，不要让用户再去查「图片一」对应的实际文件名

### 2.4 曾经困扰用户的反复问题（已根治，务必不要复发）

| 问题 | 根治方案 | 在哪 |
|---|---|---|
| 一致性漂移（风格跨 Cut 跑偏） | visual-style.md 恒定层逐字注入每条提示词，不换同义词 | seedance-storyboard-skill |
| 视频提示词混入音乐 | reviewer 按文本匹配 `M\d\d/BGM/配乐` 判 FAIL | review-methodology |
| 画幅传染 | 只在 video-prompts.md 顶部一处声明 | seedance-storyboard-skill |
| CLAUDE.md 膨胀 | 细节外置到 _shared/ 和 ARCHITECTURE.md，只留指针 | CLAUDE.md 当前状态 |
| 评分制卡在 7.9/8.0 | 改查病制，五类病 + blocking 白名单挡线 | review-methodology |
| 路径 B 死锁 | 路径 B 由导演在阶段二补 creative-brief | path-b-setup |

## 四、更新触发条件

> 用户明确说明：**下一次触发 V15 升级的条件是视频生成模型出现重大突破——某个模型在能力上显著超越当前最佳模型**（截至 2026-09-29 是 Seedance 3.0）。
>
> 日常 bug 修复和小优化仍在 V14.x 内部迭代，不触发 V15。

判断标准建议（供升级 AI 参考）：
- 新模型的单条最长时长从 30s 提升到显著更高（如 60s+），导致「无戏剧断点不拆条」的合并空间大幅扩大
- 新模型支持多角色连贯跨 Cut 生成（不再需要上传参考图维持角色一致性）
- 新模型引入用户当前配置无法发挥的新能力类型（如动态镜头序列、真实音频驱动）

## 五、升级 AI 访谈协议

**必须在动任何配置之前完成以下访谈。**

访谈目标：了解用户当前实际使用情况、本轮升级的真实诉求、哪些决策是用户自己在新一轮中已经想清楚了的。

### 5.1 开场

先做自我介绍，说明你将在访谈后开始工作，而不是直接开工。给用户看本文件「三、待办候选」这一段，问：

> 上面三个待办候选，你现在最想做哪个？哪个完全不需要做？

### 5.2 必问的核心问题（每次升级必问）

1. **模型变化**：你现在主要用哪个视频生成模型？单条最长多少秒？这个数字有没有变化？（确认是否要更新 max_seconds 相关口径）

2. **路径变化**：你现在多少比例从「选题」起笔 vs 从「已有剧本」起笔？有没有新的起笔方式（比如已有短视频想翻拍、已有小说想改编）？

3. **痛点**：上一个版本用下来，什么地方让你感到卡顿或者绕路？有没有某个步骤你每次都想跳过，但又不得不做？

4. **成片质量**：你拿提示词去生成，结果里最频繁出问题的是什么？（角色一致性 / 镜头运动 / 接缝对不上 / 其他）

5. **内容方向**：你最近主要做什么类型的内容？微电影、短剧、MV、还是别的？这个和上一版有没有变化？

6. **审美更新**：有没有某部片子或某个导演，你现在特别想往那个方向靠？（更新色卡锚点或者创作九原则的参考）

### 5.3 可选深挖（视情况问）

- 你有没有建立自己的提示词笔记或者最佳实践？有什么是配置里没有但你每次都手动做的？
- episode-master 的「用户操作清单」你实际用得上吗？还是每次都跳过自己摸索？
- retake 站用过吗？翻车最多的是哪类问题？

### 5.4 确认不动的部分

最后展示本文件「二、1 不可动的设计决策」表格，问：

> 这些核心设计，有没有哪个你现在想改？

不要假设用户想保留所有历史决策——每次升级都要明确确认一遍。
