# 分镜编译技能（v14.0 · 条头三行 + 围栏四块）

[任务]
    把已过 **★表确认** 的镜头表，逐条翻译成视频模型可直接执行的动态提示词。
    **条 = Cut = 一个生成单元 = 一条提示词**，时长上限读 `.project-config.json.video_model_config.max_seconds`。每条成品两部分：
        - **条头三行，给人看**：上传——@图片N 对应哪张图（登项目编号）；承接——从上一条怎么接、缝型；交出——本条结束状态五字段。
        - **围栏一个，给模型读**，四块顺序固定：引用声明 → 总述段 → 分段剧情 → 收尾约束。**围栏第一个字就是模型读的第一个字，围栏里没有任何给人看的东西**——零字段名、零项目编号、零元指令。
    本站是**翻译器，不是创作者**：镜头表的叙事段已经把每一镜写成了话，本站把人名换成代称、把参数行的词塞进句子、按轨分段、把每条独立所需的总述段带上，删掉模型跟不住的密度。**不改剧情、不增删镜头**——要改回 `shot-design` 改表并重走 ★表确认。
    规则集声明：本站只持**视频规则集**——负向可用但症状驱动；图像规则集归 `art-design-skill`，两套禁止串用。

    📌 **源库站名映射**（本卡及其 references / templates / examples 沿用了 Seedance 分镜师 3.0 的旧站名，**均不是真实存在的 skill 名，别去调它们**）：`motion-compile` = 本站 · `script-breakdown` = 导演拆解（`outputs/epNN/01-director-analysis.md`）· `character-design` / `scene-design` / `prop-design` = `art-design-skill`（服化道）· `control-image` = 控制图，V14 无独立站、本站兼做落 `outputs/epNN/control-prompts.md` · `director-grill` = `director-skill`。

[第一性原则]

    **followability 高于 completeness**——模型跟不住的细节宁可删。
    - **短而可跟随**：以「10s 条 400–900 字、长条不超 1500 字」为尺（完整长度尺见 templates/prompt-template.md）。超 1500 字在条头写一句理由。**长不是密度，是噪声**——每多一句不改变画面的话都在稀释注意力。
    - **每条是孤岛**：模型无记忆。总述段每条都带——视频媒介句、场域锚句、人物行、空间两行、环境声与全条光——**逐字的部分不换同义词**。为什么必须逐字：换措辞就扩大采样范围导致漂移。
    - **只在需要模型创造的地方给自由**：什么不能变、什么会变、为什么变、何时变、观众看哪、怎么结束——六问答在分段剧情里，答不上的地方模型用默认想象填。
    - **写成话不写成链**：一句一件事，有主语有动词，前一句的结果引出后一句，全是可见可听的东西。箭头链、参数堆、名词清单模型取平均。
    - **真相源纪律**：条归讲戏本、镜头数与逐镜叙事归镜头表、编号与身份归 reference-index、状态归 ledger、时间戳与 @图片N 归本站。冲突不猜，走 `references/arbitration.md`。

[编译目标]（每条成品的固定形态：条头三行 + 围栏四块）

    ## 围栏四块（给模型读，顺序固定）

    1. **引用声明**：每张上传图一句用途，句式「@图片N用于{{主体}}的{{外貌/空间/外形}}，不采用图片的{{背景/构图/姿势}}」；首帧或关键帧写「@图片N作首帧」「@图片N用于镜头M的构图与站位」。号 = 条头上传行的顺序。完整句式、场景必带继承禁令、角色行内状态公式与不串脸声明见 `references/asset-binding.md`。
    2. **总述段**：一段话，顺序——视频媒介句逐字 · 本场场域锚句逐字 · 人物行「{{代称}}——{{短串}}」（有台词的接声线锁逐字一次）· 空间两行（从镜头表场头的空间地图块压出）· 环境声一句 + 全条光一句 · 本条一句话讲什么。条件项表按本条画面有无承载物取来源版或排除版。
    3. **分段剧情**：A 轨 `[Xs-Ys]` 分段、B 轨 `镜头N` 分镜；每段 = 起因 → 动作 → 镜头看见什么 → 声音 → 段末可见状态，**写成话**。镜头句嵌在段里；台词 `{}`、音效 `<>`；首帧一句在第一段第一句；B 轨最长镜与最短镜带配重语言、条末带连续性一句。写法详 `references/dual-track.md`。
    4. **收尾约束**：一行——基础五项逐字固定、顺序固定「无字幕、无水印无 Logo、无额外人物、无动作重置、不切黑」+「无任何背景音乐」（narrative 档固定句）+ 本条附加 ≤2 项（片型项或症状项，如「全程只有她一个人」「无越轴」）。**基础五项已含「无动作重置」与「不切黑」，附加项里不许重复它们**（尾缀固定项不占附加名额）。选词与群演改写详 `references/negative-policy.md`（选词唯一真相源）。

    ## 条头三行（给人看，不进围栏）

    - **上传**：`@图片1 = char-001 名字（三格表特写格）· @图片2 = scene-001 主板 · @图片3 = ctrl-ep01-P01-Cut1-kf1 首帧`——**项目编号只出现在这里**，它是跨文件反查与对账的真相源。@ 号顺序 = 用户传图顺序，编译时就写死。
    - **承接**：缝型 + 从什么画面或状态接。三型缝写法见 [三型缝的条头形态]。
    - **交出**：`位置 ｜朝向 ｜持物 ｜动势 ｜情绪`——五字段，与镜头表条末【结束状态】逐字一致。

    🔴 **两套地址不许混**：项目编号（char-NNN / scene-NNN / prop-NNN / ctrl-epNN-P0X-CutM-<类型>）只住条头；围栏正文只说平台语 `@图片N`（= 上传顺序，每条各自从 1 数起）。**围栏内出现任何项目编号 = blocking 级缺陷**——模型不认 char-002，它只认你传进去的第几张图。

[锁/变分层法]（落笔前的第一步思考框架）

    每写一条之前，先在脑内分两层（不进产物格式，只是组织信息的方式）：

    **恒定层**（跨条不变）→ 用参考图 + 总述段的逐字文本解决，不在分段剧情里重复描述
    - 角色的外貌、服装（已在 `character-prompts.md` 与 reference-index 短串里精确定义）
    - 场景的环境、布局（已在 `scene-prompts.md` 与空间地图块里精确定义）
    - 全片视觉风格基准（视频媒介句 + 场域锚句，从 `visual-style.md` 逐字取）

    **可变层**（这一条独有）→ 写进分段剧情
    - 这一条里人物做了什么具体动作、动到什么部位
    - 镜头如何运动（景别 + 机位 + 运动 + 光学锚）
    - 情绪有什么变化（上一拍到这一拍的差异，写成肌肉级可见的）

    自检：分段剧情里有没有重复描述参考图或总述段里已固定的外观？有 → 删掉，只留动作、运镜与声音。
    ⚠️ 分层是减少冗余的原则，**不等于省略参考图**——[可判定自检] 第 ③ 条依然有效。
    ⚠️ 分层也**不等于省略总述段**——总述段是「每条是孤岛」的落地，每条都要带全。

    🔴 **提示词不是越长越好**。已经传了主体和场景参考图，就不要再用文字把长相、衣服、房间陈设重复一遍——没有意义，还会和参考图打架。
    一条好的提示词，你自己读一遍应该觉得清爽、一眼知道这条要发生什么。**如果一段提示词连你自己都读不完，说明你对这条要发生什么其实并不关心**——回去看镜头表这条的戏是什么，再写。

[翻译法]（每条按序走六步）

    1. **选轨与松紧**：按 `references/dual-track.md` 决策表选 A/B 轨，定紧/松档。**B 轨为主**（对话正反打、多人调度、密集动作）；**A 轨只给**一镜到底 / 叙事时间轴 / UGC 生活流 / MV 广告卡点。正片一律紧档。
       🔴 三根轴不许混：**节奏紧/中/疏**（导演给的，管时长）≠ **松/紧**（本站的，管放权，只两档）≠ **控制等级 L1–L4**（镜头表的，只管要不要控制图）。
    2. **装总述段**：取四件基准文本的对应项，压空间两行，写人物行与声线锁，一句环境声一句全条光，末尾一句本条讲什么。装完回读：**总述段里点名的东西本条画面里都看得见吗？看不见的删。**
    3. **翻分段剧情**：
       - A 轨：把镜头表各镜按时长合并成 `[Xs-Ys]` 段，时间轴 0 起、无重叠无缺口、末点 = 本条总时长；段内容量自平衡（显式时长要求求和 < 段长）。
       - B 轨：一镜一段，**全条零秒数**，长短分配走配重语言通道（「本条最长的一镜，占全条约三分之一」「一拍即过」）。配重语言与秒数**互斥**——两个通道只许开一个。
       - 每段把叙事段翻成话：人名换代称、参数行的景别机位运动光学压成一句镜头句嵌进去、表演行压成一两句可见行为、空间行压成站位句；台词逐字带记号与语气；音效绑动作。
       - **五维过一遍**：运镜与光学 `camera` · 空间 `blocking` · 表演 `performance` · 光 `lighting` · 声音 `sound-writing`——**有人物出镜的条五维都要在句子里指得到落点**，空镜可缺表演。
       - **物理分解纪律（v15.0 · Seedance 2.5，有人物动作的镜必须过全部五条）**：
         1. **情绪→肌肉翻译**：写表演前先把情绪状态翻译成肌肉/身体反应，再写可见动作句；禁止直接用情绪形容词进围栏。常用映射：焦虑→斜方肌拉紧/呼吸变浅/手指无意识摩擦；愤怒→咬肌收紧/颈静脉隐现/手握成拳；悲伤→眼轮匝肌松弛/嘴角微坠/肩向内扣；欢愉→颧骨上提/眼角皱纹出现/胸腔扩张。
         2. **全身动力链四层**（全身运动时必须覆盖全四层）：① **主动件**（发力关节）② **稳定件**（对抗发力、维持平衡的部位）③ **补偿件**（被动跟随运动的部位）④ **不自主反应**（微表情/皮肤/衣料的被动响应）。写法示例：「她抬手（主动件：肩肘腕发力）→ 核心收紧（稳定件：腰腹对抗）→ 外套随之撩起（补偿件：布料被动跟随）→ 颈侧细纹在光下一瞬显现（不自主反应）」。
         3. **环境动态**（每镜 ≥3-4 项，从以下类取够）：风/水流/烟/尘/布料飘动/树叶/纸张/人群密度变化——写具体物件和变化方向，不写「背景有些动」。
         4. **四层画面枚举**（每镜必须指到全四层）：**前景层**（镜头最近层，常用于构图遮挡）/ **中景层**（主体所在层）/ **背景层**（纵深感来源）/ **空气层**（光束/雾/尘埃/热浪，赋予镜头「厚度」）。空镜可缺中景层，其余三层不可缺。
         5. **光-表面交互**（每镜至少一句）：指明光源 → 照射面材质 → 表面反应。示例：「侧光打在青砖墙上，砖缝阴影把纵深拉出三个层次」；人物皮肤受光面、衣物材质高光/漫反射、关键道具的光泽感一并交代。
    4. **写收尾约束一行**：症状负向按 `references/negative-policy.md` 只写本条真有的，附加 ≤2 项。
    5. **写条头三行**：@图片N 号按引用声明首次出现顺序从 1 编；承接按缝型写；交出五字段抄镜头表结束状态。
    6. **量长度**：对照 templates/prompt-template.md 的长度尺。超尺先删——重复的外观描写、并列无因果的动作、与画面无关的形容词、第二遍出现的空间与声音描述。

[生成模式判定]（T2V / I2V / V2V，先读能力标志再定）

    | 模式 | 前提条件 | 适用场景 |
    |------|---------|---------|
    | **I2V**（图像转视频） | `supports_image_ref=true` | 画面中有具名角色 → **默认选这个** |
    | **T2V**（文本转视频） | 无前提 | 画面中**完全没有具名角色**（纯环境 / 纯特效 / 纯 UI 全屏） |
    | **V2V**（视频续接） | `supports_video_ref=true` | 真帧缝续接、后期精修专用 |

    - `supports_image_ref=false` → 全集强制 T2V，条头上传行写「无（工具不支持参考图）」。
    - `supports_video_ref=false` → V2V 禁用，真帧缝降级为遮挡缝，见 [三型缝的条头形态]。
    - `supports_audio_ref=true` 才在条头上传行加 `@音频N` 槽；否则声线只靠总述段的声线锁文字。

    🔴 **T2V 判定红线**：只要画面中有具名角色出现，无论叠加多少特效 / UI，都必须走 I2V 上传角色参考图。特效和 UI 是叠在角色上面的一层，不会让角色消失——没有参考图，模型会凭空捏造一张与原设计毫无关系的脸。
    **T2V 条的补偿写法**：因无参考图，总述段的人物行必须把体型 / 发型 / 服装颜色等关键可见特征写进去（这是 T2V 唯一允许在文字里描外观的地方），且全集同一角色的这段文字逐字一致——不一致就是每条一张新脸。

[三型缝的条头形态]（承接行怎么写；写法真相源在 references/transition-vocab.md）

    | 缝型 | 条头承接行写法 | 依赖 |
    |---|---|---|
    | **无缝**（本场首条 / 本集首条） | 「首条，无。开场状态取自台账 / 讲戏本开场」 | 无 |
    | **遮挡缝**（默认，最省） | 「遮挡缝：从{{静帧 / 遮挡物 / 暗场}}起幅 ≥1s，与上条各自独立生成」 | 无——两条互不依赖，可并行生成 |
    | **真帧缝**（要帧级连续时才用） | 「真帧缝：上传 Cut{{N-1}} 成片尾帧作 @图片{{K}}，从「{{上条交出的画面一句}}」继续」 | 依赖上条已生成；`supports_image_ref` 或 `supports_video_ref` |
    | **延长缝**（同一镜头续时长） | 「延长缝：对 Cut{{N-1}} 成片向后延长 {{N}}s，只写新增段」 | 依赖上条已生成 + 工具支持延长 |

    真帧缝的代价：生成顺序被锁死（这条必须排在它依赖的条之后），且尾帧质量直接决定本条起幅质量。**默认用遮挡缝**——衔接靠设计层的呼应，不靠让模型对齐帧。
    `supports_video_ref=false` 且 `supports_image_ref=false` 时真帧缝无法实现 → 降级遮挡缝，并在 episode-master 的风险列标注。

[双轨模式判定]（故事板是手动支路，不是默认路径）

    **故事板只有用户明确开启才用，其余一律走单镜正路。** 很多人花十几分钟生成一张华丽的故事板——带镜头运动曲线、各种标注和表格——丢进视频模型反而错漏百出：模型会把标注线、箭头、表格当成画面内容一起渲染，一张图里挤了角色/场景/分镜，任一处漂移整段废。所以故事板不作为默认路径，也不由分镜师或导演自行决定。判定只有三级：

    1. 用户单集锁定：`.project-config.json.storyboard_overrides[<当前集数>] == "storyboard"` → 本集走故事板支路
    2. 用户全局锁定：`.project-config.json.storyboard_overrides.global == "storyboard"` → 走故事板支路
    3. 以上都不命中（含字段不存在、值为 single-shot）→ **单镜正路**。导演讲戏本的「镜头承载规划」只影响定镜，不影响模式。

    单镜正路下不需要向用户解释选择理由。只在故事板支路下告知：

        【模式选择】
        本集按你的锁定采用故事板模式（storyboard_overrides 命中）。
        如需回到单镜请用：~storyboard-mode single-shot [<集数 / global>]

    **控制图同为手动**：用户明确要求才生成，提示词落 `outputs/<集数>/control-prompts.md`；不要求则条头标「无控制图」，纯资产图绑定。

[故事板模式流程]（仅上述判定命中时执行；围栏结构不变）

    1. **风格决策**（读 `references/storyboard-style-decision-tree.md`）
       - 4 维度判定（用户偏好 → 题材 → 复杂度 → visual_style），输出 5 候选之一：cinematic_realism / disney_3d_animation / epic_realism / commercial_clean / black_white_manga_lineart
       - 主动告知：

            【故事板风格判定】
            本片故事板风格 = <风格名>
            判定理由：<维度 X 命中——具体理由>
            如需覆盖请用：~storyboard-style <名>

    2. **模块组合判定**（读 `references/universal-storyboard-methodology.md` §四）：必备 6（M1–M6）+ 可选 4（O1 场景状态图组 / O2 关键道具 / O3 对白气泡 / O4 十六进制色板）按场景挑选。

    3. **写故事板提示词文件**（按 `image_model_config.grid_mode` 决定结构）
       - `grid_mode = "single"`：每 Cut 一份，路径 `outputs/<集数>/storyboards/P0X-CutN-storyboard-prompt.md`；只描述该 Cut 的单帧画面（风格段 + 构图 + 角色 + 情绪 + 光照），无宫格排版段。P 编号与讲戏本对齐，Cut 编号与 video-prompts.md 对齐。
       - `grid_mode = NxM`：每 P0X 一份，路径 `outputs/<集数>/storyboards/P0X-storyboard-prompt.md`；含 M6 衔接 frontmatter + 核心目标段 + 整体风格段 + 画面结构段 + M1–M6 + 选用 O 模块 + 限制段 + 排版段（写出宫格配置，如「按 2列×4行 布局，每格一个 Cut 的定格画面」）。本 P0X 镜头数 > 宫格格数 → 提示用户拆 P0X 或用 `~image-model` 切单张。
       - 故事板大图默认 16:9 横版（信息密度最大化），这是**生图工具的画幅**，与最终视频画幅无关——视频画幅只在 video-prompts.md 顶部声明，见 [画幅声明]。

    4. **衔接**：每个 P0X 的 frontmatter 填 from_previous + to_next（五维度：位置 / 道具 / 光影 / 环境 / 情绪），内容来自导演讲戏本前后剧情点，前期一次性设计完；首段填「无（开场）」、末段填「无（结尾）」。详 `references/transition-mechanism.md`。

    5. **写 video-prompts.md**：**围栏四块结构与单镜正路完全相同**，唯一区别是引用声明块里资产图换成一张故事板图——「@图片1用于本条的构图与站位（该图第 N 格），不采用其分格框、标注线与表格文字」。项目视觉风格仍走总述段的媒介句 + 场域锚句，**不采用故事板大图自身的 5 候选风格**（两者解耦）。

    6. **用户操作提示**（写进 episode-master.md 的用户操作清单）：先按 grid_mode 逐份生成故事板 PNG 并归档到 `outputs/<集数>/storyboards/`（与 `-prompt.md` 配对命名），再拿 video-prompts.md 逐 Cut 生视频，**在工具里手动选顶部声明的画幅**，最后剪辑串接。

[可判定自检]（每条编完必做，可数可对照，双支路通用，只在此处定义）

    **① 围栏纯净**：围栏内无字段名（「镜头语言：」「参数：」）、无项目编号（char- / scene- / prop- / ctrl-）、无元指令（「严格承接上一条」「同上」）、无给人看的话（条头信息、注脚）。
    **② 四块齐且顺序对**：引用声明 → 总述段 → 分段剧情 → 收尾约束，一块不缺、不换序。
    **③ 参考图覆盖**：分段剧情里出现的每个具名角色 ⊆ 条头上传清单；条发生在具名场景 → 该场景图 ∈ 上传清单。**每条是独立生成任务，模型没有记忆——上一条传过的场景图，这一条仍要传。** 群演 / 无名路人不算具名角色，文字描述即可。
    **④ 号连号且对得上**：@图片N 与条头上传行逐项对得上、从 1 起连号无跳号；人物图只在引用声明 @ 一次，正文改用代称；场景引用带「不采用其构图」。
    **⑤ 逐字项一致**：视频媒介句、场域锚句、短串、声线锁、空间地图行与源文件逐字一致；场域锚句是**本场**那一句；条件项取对版本（来源版 / 排除版）。
    **⑥ 人物指代可解析**：正文每个人物指代都在引用声明或总述段建立过「名字 → @图片N → 可视特征」三元映射；多人同框有「各角色严格对应各自参考图，不串脸」。详 `references/asset-binding.md` [人名与代称 · 六条铁律]。
    **⑦ 轨型合规**：A 轨时间轴 0 起、无重叠、无缺口、末点 = 总时长，每段显式时长要求求和 < 段长；B 轨**零秒数**、最长镜与最短镜有配重语言、条末有连续性一句。
    **⑧ 配重与秒数互斥**：B 轨条内没有任何「约 N 秒」「N 帧」式补充说明——给了配重就不再补秒数。
    **⑨ 五维有落点**：有人物出镜的条，camera / blocking / performance / lighting / sound-writing 五维都在句子里指得到落点（空镜可缺 performance）。
    **⑩ 台词合规**：与镜头表逐字一致，带记号与语气，按 [台词类型] 打对标签；画外角色名不进分段剧情。
    **⑪ 音乐隔离**：围栏内含「无任何背景音乐」，且除此之外不出现 `M\d\d` 编号、BGM、配乐、音乐、主题曲、旋律字样。M 编号只在围栏外的 🎵 注脚。见 [音乐隔离]。
    **⑫ 时长范围**：`min_seconds` ≤ 本条时长 ≤ `max_seconds`（均来自 `.project-config.json.video_model_config`）；**B 轨围栏内零秒数**，A 轨秒数只作因果段落划分。见 [时长预算与定镜]。
    **⑬ 自洽性**：围栏不引用其他条或其他角色来解释本条（「与赵克用的仰拍形成对比」「延续上一镜的氛围」→ 改写为本条自洽的可见描述）。问：如果这是唯一一条，模型能执行出正确画面吗？
    **⑭ 条头对账**：承接的缝型与镜头表接缝行一致；交出五字段与镜头表【结束状态】一致；本场首条承接台账或上场快照。

    🔴 **结束状态五字段是全套脊椎，四处必须同步**：镜头表条末【结束状态】→ 条头「交出」行 → 台账落幅 → 缝审计第 1 查。任一处不一致就是断链。

[台词类型]（核心判据：模型是否需要生成嘴唇动作）

    | 类型 | 标签 | 角色嘴巴 | 典型场景 |
    |------|------|---------|---------|
    | 开口台词 | `台词（角色名，开口）：` | **要动** | 角色当场说出的话 |
    | 低语/耳语 | `台词（角色名，低语）：` | **轻微动** | 极轻声、贴耳说、压制的低吼 |
    | 内心OS | `内心OS（角色名，不开口）：` | **不动** | 内心独白（后期配音，嘴不动） |
    | 回忆音 | `回忆音（角色名，不开口）：` | **不动** | 脑海中浮现的声音 / 往事 |
    | 画外声音 | `画外音（不入画，描述声源）：` | 不在画面 | 另一人说话但不入画；旁白 |

    用错标签会让内心独白变成开口台词、角色「嘴动了」，画面废掉。
    开口台词要让模型理解这句话怎么说——情绪、语气、节奏，写法不限（内联标注、标点暗示都行）；有声线锁的角色在总述段引一次，正文不重复。

    🔴 **画外音的两步写法**：
    第一步（视觉防污染）：画外角色的名字**不能出现在分段剧情里**——模型看到任何人名都会把他当成视觉生成对象。
    ❌ 「赵克用的话在画外响起」 → ✅ 「低沉施压的男声在画外响起」
    第二步（内容具体化）：声音写清说了什么、什么语气。
    ❌ 「赵克用的施压台词」 → ✅ 「画外低沉施压男声：{陈稳，账上少了三千斤铁，给本官一个交代。}」
    如需在总述段交代画外的权力关系，用中性描述不出人名：「这是一场审讯，弱势方在画内，画外传来上位者的盘问声。」

[音乐隔离]（结构规则，不靠叮嘱）

    🔴 **绝对不生成任何 BGM。音乐一律由音乐总监单独做歌，其他 agent 一概不碰。**
    音乐（BGM / 主题曲 / 配乐 / 段落动机）**不进围栏**，只以围栏之外的独立注脚行出现：
    `🎵 后期铺乐：M01 主题曲，铺在 Cut 3–8。（此行在围栏之外，请勿复制到生成工具）`

    **围栏的收尾约束行必须正向写出「无任何背景音乐」**。只在心里想「不要音乐」不够——模型看到空白的声音槽会自己配乐，**不写 BGM 指令的条，模型会自作主张塞配乐；沉默也要写出来**。同时总述段要给它该出的环境声一句，音效绑在动作上。
    为什么这条是硬红线：成片是把 N 段独立生成的视频拼起来。任一段自带音乐，与相邻段的音乐对不上（调性、节奏、起止位置全都错），这段就没法剪——整段废掉重生。环境音 / 音效 / 台词不冲突，还省去拟音。

    **分档**（真相源在 `sound-writing`）：
    - `content_type = narrative`（默认）→ 围栏内固定「无任何背景音乐」+ 音乐总监后期铺。
    - `content_type = mv` → 例外档：画面跟音乐走，按 `sound-writing` 的 mv 句式写有乐句，并对齐 mv 音乐时间轴的节拍点。

    讲戏本里的「此处响起 M01」是给后期的标记，不是提示词内容。故事板的 M5 声音设计模块可写 M01 编号（那是给人看的视觉信息，不进视频生成）。

[画幅声明]

    画幅只在 `video-prompts.md` **顶部声明一次**：「本集所有 Cut 视频画幅 = `settings.aspect_ratio = <实际值>`，生成时在工具里手动选此画幅。」
    条内一律不写画幅。故事板大图的 16:9 是生图工具的画幅，与视频画幅无关。

[群演/一次性配角处理]

    镜头表中不在 `character-prompts.md` / `reference-index.md` 里登记的人物（群演、一次性配角）：**不上传参考图**，在分段剧情里直接用可视特征文字描述其外观和动作（外观从导演阐述中提取），且全条前后一致。
    故事板支路下，群演不出现在 M2 角色参考模块，可在 M4 分镜网格的 Cut 描述中文字提及。

[时长预算与定镜]（编译时只校验与落位，不改条——改条回 shot-design）

    ## 一、先算预算，再看表

    开工前把两个数字摆在桌面上：

    | 数字 | 来源 | 作用 |
    |---|---|---|
    | **单条上限** | `.project-config.json.video_model_config.max_seconds` | 一次生成最多能承载多长的连续戏 |
    | **目标成片总时长** | `assets/story/script-settings.md` 的总时长 / 每集时长 | 这一集总共要多少秒 |

    两者相除得到**条数的量级**：总时长 ÷ 上限 = 理论最少条数。这不是配额，是让你知道自己在什么尺度上工作。
    例：3 分钟成片、上限 30s → 理论最少 6 条，实际按剧情可能 8–12 条；同样 3 分钟、上限 15s → 理论最少 12 条，实际 15–25 条。**同一个剧本，上限不同，分镜方案根本不是一回事。**

    ## 二、上限决定「一件事用几条讲」

    上限不是末尾的检查项，是设计起点（这一节的判断发生在**第一步落表时**，编译时只做校验）：

    - **上限紧（如 15s）**：一个完整的戏剧动作常常装不进一条，你被迫拆——「他推门 → 看见桌上的信 → 拿起来读」得切三条。这是**妥协**，每一次切都是一个接缝，接缝处的光线、角色、运镜都要靠承接 / 交出对齐。
    - **上限宽（如 30s）**：同一段戏一条到底，推门、发现、阅读、脸色变化全在一个连续条里演完。**没有接缝就没有对齐问题**，光影连续、表演连续、音效连续，质量天然更高，后期只需把条按顺序排好。
    - **上限极宽**：分条的概念本身会松动——整场戏甚至整片可以一次生成，那时工作重心从「怎么切」彻底转向「怎么讲」。

    所以：**上限越宽，越应该主动把戏做长、做连续，而不是习惯性地切碎。**

    ## 三、榨干上限（在剧情允许的前提下）

    落表时每定一条，问一句：**这一条还能不能多承载一点戏，而不牺牲质量？**

    典型可以合成一条的情况：
    - 同一人物、同一空间、时间连续，前后动作有因果（一个 8s 的动作 + 一个 15s 的动作，加起来 23s ≤ 30s → **合成一条，不要生成两段再去剪**）
    - 一个连续的运镜可以串起多个信息点（推近过程中依次露出：人的手 → 桌上的信 → 他的脸）
    - 对话的一个来回（两三句台词，同一机位或一次自然的摇移就能完成）
    - 一个动作的完整弧线（起势、发力、结果、余韵——切开反而失去力量）

    **不该合的别硬合**：空间或时间跳切；需要换景别 / 机位才成立的对比（全景的孤独 vs 特写的眼泪）；情绪节拍需要「停一下」的留白，切开本身就是表达；合成后单条承载的动作太多、模型跟不住 → 宁可切开。

    判据：**这一条如果一气呵成拍出来，观众会觉得更顺、更有临场感吗？** 会 → 合。会觉得赶、乱、跟不上 → 分。

    ## 四、条内分镜用镜号，不用时间戳（B 轨）

    🔴 **B 轨条内不给动作加时间戳**。`[0-3 秒] 推近` `[4-8 秒] 转身` 这类写法是安慰剂——模型不会真按时间戳分配时长，写了只是让提示词变长、还束缚它的发挥。
    真正影响生成结果的是**条内切了几次**，以及各镜的相对轻重。所以一条内有多个连续动作时，用 `镜头1` / `镜头2` / `镜头3` 排序，按事件先后写，每镜一句话说清动作，长短分配走**配重语言**（最长镜与最短镜必写）。

    ```
    ❌ 本条 15s：[0-3秒] 陈稳低头看账本 [4-9秒] 抬头 [10-15秒] 起身
    ✅ 本条 15s：
       镜头1：陈稳低头翻账本，指尖停在某一行。
       镜头2：他猛地抬头，喉结滚动一次——本条最长的一镜，占全条约一半。
       镜头3：起身，凳子向后刮出刺耳一声——一拍即过。
    ```

    A 轨的时间戳是另一回事：它划的是**因果段落**，不是给条内分镜派秒数，写法与硬规则见 `references/dual-track.md`。

    ## 五、交付的是乐高 + 说明书

    最终产物不是一堆零散条，而是**一套能拼成完整作品的组件 + 一份拼装说明**：
    - 每条是一块**边缘规整**的乐高：起止状态明确、画幅一致、无自带音乐、风格锚一致——这样才拼得上
    - `episode-master.md` 是**说明书**：条的顺序、每条用哪些素材、缝在哪、音乐铺在哪几条
    - 检验标准：用户拿着这两样东西，能不能**不做二次创作**就把成片拼出来？需要他自己猜、自己补、自己修接缝 → 你的活没干完。

[落盘与重编号]

    写入 `outputs/<集数>/video-prompts.md`，按 P0X 分节、形态照 `templates/prompt-template.md`。文件头两行固定：版本行（版本 ｜ 状态 ｜ 最后更新 ｜ 镜头表 v ｜ 资产索引 v ｜ 风格基准 v）+ 怎么用行（每个围栏 = 一条整段复制去视频工具的提示词；围栏外是给人看的；图片按条头「上传」行的顺序传，@图片N 的号就是传图顺序）。
    编号：Cut 1 / Cut 2 / … / Cut N，**全集连续**，与镜头表条号一一对应，不跳号不复用。
    每个 P0X 编完 → 按 `continuity` 更新 `assets/continuity-ledger.md`（落幅五字段追加式登记，不回改历史）。**不更账 = 没编完。**

    🔴 **retake 改绑定集时的重编号铁律**：增删换参考图使某条的绑定集变化 → **该条 @图片N 整条重编号**，在 `video-prompts.md` 同一文件里把条头「上传」行与围栏内所有 `@图片N` **一次改齐、从 1 起连号**，改完动手复核连号与残留。同文件同步改不产生跨文件替换，其他条不受影响。本条是 `retake` 引用的真相源。

[输出 episode-master.md]（强制要求，全集编完才算交付）

    按 `templates/episode-master.template.md` 输出 `outputs/<集数>/episode-master.md`，必含 7 段：
    1. 本集基本信息（项目 / 集数 / 总时长 / 剧情点数 / 模式 / 故事板风格（如有）/ 视觉总锚 / 视频模型 + max_seconds）
    2. 全片衔接表（每条一行：缝型 / 承接 / 交出 / 风险）
    3. 故事板提示词表（仅故事板支路）
    4. 视频提示词表（Cut 号 → 时长 → 轨型 → 上传清单）
    5. 资产清单（引用到的 reference-index 编号与文件名）
    6. 音乐编号对应（M01–M0N → 铺在哪几条，关联音乐总监输出）
    7. 用户操作清单（生成顺序：资产图 → 控制图（如有）→ 视频条，真帧缝的条排在它依赖的条之后；每条上传什么；第一条试片看什么；翻车回哪；后期三件——硬切遮挡缝、铺 BGM、字幕）

    跳跃风险标记：⚠ 时间跳跃 / ⚠ 空间跳跃 / ⚠ 情绪跳跃 / ⚠ 角色跳跃 / ⚠ 道具消失，应对见 `references/transition-mechanism.md`。

[完成标准]（动手核，不凭「看起来对」；查出的当场修，修完才交）

    1. 每条跑过 [可判定自检] 全 14 项，逐项给得出证据。
    2. 条数与镜头表条数一致；Cut 号连续；每条时长在 `[min_seconds, max_seconds]` 内。

    4. 逐字项与源文件一致：媒介句、场域锚句、短串、声线锁、空间地图行、台词。
    5. 轨型合规：B 轨零秒数 + 配重 + 条末连续句；A 轨时间轴 0 起无重叠无缺口、末点 = 总时长。

    9. 数量预算：单条主体 1–5，图 ≤9 / 视频 ≤3 / 音频 ≤3 为稳定区（详 `references/asset-binding.md` [数量预算]）。

[底线提醒]
    > 提示词是手段，戏才是目的。
    >
    > 每编完一条，问一句：**这一条的戏是什么？** 答不出来，格式再规范也是废片——回去看镜头表，别靠堆细节掩盖。
    > 你的价值不在写得多全，而在把镜头表讲的戏准确翻译成模型跟得住的话。参考图能交代的交给图，总述段能锚定的交给逐字文本，剩下的只写「动」。
    > 详见 CLAUDE.md [效率去哪儿]。
    >
    > 故事板同理：手段不是目的。用户没开启就不用，开启了也别为了故事板而故事板。
    > 衔接保障来自五层：资产复用 + 风格锁定（逐字项）+ 剧情连贯（编剧 / 导演前期已设计）+ 承接 / 交出对账 + 后期剪辑——**不靠让模型对齐帧**。
