[定位]
    绑定段是整条提示词的产权声明：每份参考资产控制什么、不控制什么，一句话写死。未指定职责的资产会被模型默认混合使用——多参考互相污染的根源就在这里。
    三条铁律：
        1. 每个 tag 在绑定段恰好出现一次——tag 即本条的平台地址 @图片N；tag 重复出现是生成拒绝启动的头号原因；正文不重复 @，改用自然语言代称，代称的合法条件见 [人名与代称 · 六条铁律]。**本条是全库「tag 出现次数」的唯一真相源**：`outputs/epNN/control-prompts.md` 里的 connector 母版、站位图与关键帧标杆例一律是本条的只读引用，凡其示范让某个 tag 多出现一次，以本条为准，按 [控制图绑定] 的回指去 @ 规则改写后再入块——上游怎么写是上游的书写便利，进本条即按本条计数。本铁律只有两个法定例外，其余一律一次：一是角色行内状态公式的第二次 @，它是绑定条目的第二行，见 [角色行内状态公式]——照母版写必然出现这一次，不算违规；二是关键帧序列在正文所辖时间段或镜号处的二次点名，它落在正文、不落在绑定段，见 [控制图绑定]。站位图、轨迹图、白模、深度图、宫格与任何角色/场景/道具图都不在例外内，多写一次即违规。
        2. 先职责后 @：每条绑定先一句话说明职责，再落 @图片N。
        3. 影响最大排前：角色 → 场景 → 道具 → 控制图 → 用户自带视频/音频。这一条同时把上传顺序定死了——@ 在本段的首次出现顺序 = 用户传图顺序，编译时就已确定，所以条头清单能直接写死号、正文能直接写 @图片N，用户拿到手不必替换一个字。
    两套地址，一次翻译：项目编号是全库通用语与唯一真相源——资产编号住 assets/reference-index.md，形如 char-NNN / scene-NNN / prop-NNN，变体 -vN；控制图为手动可选产物，编号格式的唯一真相源是本卡下述规则（V14 无独立 control-image 站，控制图提示词落 outputs/epNN/control-prompts.md）：ctrl-epNN-P0X-CutM-<类型>，**不带版本后缀**，带 -vN 的完整串只活在产出卡、谱系行与版本记录里；cN 是条号、不补零；<类型> 取六个固定缩写：kf1–kfN 关键帧、grid 宫格底板、stg 站位图、traj 轨迹图、wbox 白模底片、depth 深度图。编号逐字取自 reference-index 与 outputs/epNN/control-prompts.md 的产出卡，不自拟、不改写。@图片N 则是平台会话内地址 = 上传顺序，每条各自从 @图片1 数起。分工写死：项目编号只出现在条头「上传」行的编号位（一行制：`@图片N = 项目编号 名字（形态括注）· …`，不是分列表格）——那是跨文件反查与对账的真相源；进了生成框的正文一律只说平台语 @图片N，一个项目编号都不许残留——模型不认 char-002，它只认你传进去的第几张图。号是位置不是身份：同一个角色这条是 @图片1、下条可能是 @图片2，每条各自数，绝不跨条抄号。用户自带的视频与音频走另外两条上传轨，没有项目编号，沿用 @视频N / @音频N，各自从 1 数起；白模底片是控制图中唯一的视频形态——同走视频轨、翻译成 @视频N，但它有 ctrl 项目编号，条头清单照登。

[主句式 · 唯一职责 + 反向排除]
    每条绑定 = 「{{名字}}，这是该{{角色/场景/道具}}的参考 @图片N，作为其唯一……参考；不得继承……」——先说是谁的什么参考、再落 @图片N，正面写清它管什么，反面写死它不许带进来什么。全库一套形态，母版与标杆同形，不另立第二套。下面各例的号按「角色 → 场景 → 道具」的常见排布示范，实号以条头清单为准。
    角色：
        陈伯，这是该角色的参考 @图片1，作为其唯一身份、面部、年龄感、发型、身体比例、服装与固有配饰参考；不得继承该图的中灰背景、定妆站姿与表情。
    场景——必带继承禁令，一次都不能省：
        修表铺内景，这是整个拍摄场景的参考、不是片中某一帧 @图片2，作为其唯一空间结构、固定物体、材质、纵深与光源方位参考；只控几何、材质、光线、氛围，不控构图（Controls geometry, materials, light and atmosphere ONLY — not framing）；保持左右关系、入口与消失点不变。
        不加继承禁令的后果：模型交回一张场景板的近似复制品，构图被参考图锁死。
    道具：
        黄铜怀表，这是该道具的参考 @图片3，作为其唯一外形、尺寸比例、材质与开合结构参考；当前由陈伯右手持有、表盖开启；不得继承其拍摄底座与展示背景。
        道具必须追踪：持有者、左/右手、朝向、完整/破损/开合状态——运动中的道具会复制、会换手，状态不写就漂。
    用户自带动作/运镜视频，有才绑：
        @视频1 仅作为【8-14秒 · 夺刀动作】的动作顺序、身体重心、接触关系与速度节奏参考；人物身份、服装、场景与画面风格仍由专用资产控制；不得用于其他段落，不得保留该视频的画面质感。
    用户自带音频，有才绑；默认无音频素材，声线靠声线锁文字：
        台词："……" 音色参考@音频1，保持低沉克制的语调。

[角色行内状态公式 · 绑定条目的第二行]
    每个角色绑定条目在职责句后附一行当前状态，公式，双语：
        @图片N: age + role/body type + current state + critical visible anchors + action-critical prop/body state. 100% matches the reference.
        （@图片N：年龄 + 角色/体格 + 当前状态 + 关键可见锚点 + 与本条动作相关的道具/身体状态。与参考图完全一致。）
    典型例子：
        @图片1：六十四岁，清瘦驼背的修表匠，深夜打烊时分，藏青围裙沾着机油渍，鼻梁上架单眼放大镜，右手拿一块软布——与参考图完全一致。
    怎么认：
        写对的判据是只写本条用得上的状态与锚点。禁写完整五官、参考图里已明确的服装细节、与本条无关的旧伤——"Do not overwrite the reference with excessive prose."（不要用过量散文覆写参考图。）参考图是身份真相源，散文过密反而覆写它。
    认错长什么样：
        状态行抄了 reference-index 的密版全文——发色瞳色骨相逐项——既挤运动预算，又因措辞微差诱发漂移；状态与 ledger 不符，如上条落幅左颊带伤、本条状态行写"面容干净"。

[人名与代称 · 六条铁律]
    模型不认名字，只认参考与特征——"老周走向门口"里的"老周"对模型是空词，它不知道老周是谁。六条逐条过，缺一条即为正文留了模型解析不了的指代。
    1. 先绑定，后指代——正文出现的任何人物指代，必须在本段建立过「名字 → @图片N → 外观特征」三元映射；未建立映射的名字禁止进正文。地址换了形态，三元映射一个环节都不少：名字给人读，@图片N 把脸钉在用户传的那张图上，特征让模型在画面里认得出是谁。
    2. 代称优先用可视特征词——能用身份词或外观词就不用纯人名：掌柜、军官、穿灰长衫的男人、戴顶针的老人；纯人名只在已绑定且同框无可混淆同类时用。判据：把这句单独拿给没读过绑定段的人看，他能不能指出画面里是谁；不能就换词。
    3. 恒定层必带出场人物短串——【全局设定】的出场人物行逐条写「名字（短串）」，短串自 reference-index 逐字取、不另写、不另配方——配方归 character-design，本卡只要求逐字，让名字在正文里始终挂着特征。
    4. 多人同框必加不串脸声明——两人及以上出场时，绑定段末尾逐字写「各角色严格对应各自参考图，不串脸、不互换身份」，脸与穿搭都在这一句的管辖内，全库同形不另译；单人条对应的官方写法是「全程同一人不变形」。
    5. 上游文档不受此限——讲戏本、镜头表这类给导演看的中间表示可以自由用人名；把人名翻成「绑定 + 特征代称」是编译时的职责，不是上游的。
    6. 图像提示词同理——角色图提示词正文不写角色名、只写特征：那条提示词本来就是在定义这个人长什么样，名字对图像模型同样是空词。
    典型例子：
        绑定段有「周慕山，这是该角色的参考 @图片1，作为其唯一身份、面部……参考」，紧跟状态行「@图片1：五十岁掌柜，藏青长衫，左眉一道旧疤……」，恒定层出场人物行写「周慕山（五十岁掌柜，藏青长衫，左眉一道旧疤）」，正文写「藏青长衫的掌柜转身走向门口，左手仍按在柜台上」；同框另有军官时，绑定段末尾补不串脸声明。
    认错长什么样：
        正文写"老周走向门口"，而绑定段从未交代老周是谁——模型把名字当无意义音节，随机发一张脸；或三人同框只点名字不给特征，模型按几张参考图的平均值发牌，串脸就在这里发生。

[控制图绑定 · 有 control-prompts.md 产物才用]
    控制图是**手动可选产物**：用户明确要求才生成，提示词与绑定块落 `outputs/epNN/control-prompts.md`（V14 无独立 control-image 站，该步由分镜师兼做）；它交来的绑定块用 ctrl 项目编号书写，编译时由本站统一翻译成本条的 @图片N，同时把该 ctrl 编号登记进条头「上传」行（一行制，追加一段 `· @图片N = ctrl-… 形态括注`）。翻译动两处形态、不动一个字的语义——职责句、反向排除、作用域照搬：一是该块自己的 ctrl 编号换成本条的 @图片N，二是块内对已绑资产的回指去 @。本卡只给各类型的形态对照，不另立第二套句式；原编号串形态见 [定位]，不带 -vN——版本由产出卡解析，成品端永不写死版本；下列句式里的 @图片N 是槽位，落笔换成条头清单上该图的实号。
    回指去 @ 是铁律 1 在控制图上的落地手法。控制图块为自足而反复回指场景与角色——「三人面孔、服装以 @char-001 @char-002 @char-003 为准」「一切风格光线只来自 @scene-004 与角色参考」「@A = 哑蓝人物 = @char-001」——这些资产在本段前面已经各绑过一次，回指再挂一个 @ 就是同一 tag 的第二、第三次出现，直接撞铁律 1。落笔一律去掉 @、换成不带地址的代称：「以各角色参考为准」「只来自场景参考」「= 黑雨衣的男人」。语义分毫不损——代称在本段上文已建立三元映射，模型认得出是谁；@ 只留给该块自己的控制图。字母句柄 @A/@B/@C 是提示词内句柄不是平台地址，不进条头清单、不计入 tag 次数，但图例行右侧必须落到可视特征代称上，不许落回 @char-XXX。
        - 关键帧序列，二次 @ 的位置是硬规则：绑定块内只写一次顺序声明「以 @图片K 至 @图片M 的顺序作为本条关键帧，画面按此顺序依次到达各帧所示内容，顺序 = 时间顺序」；逐帧归属不写在这里。上传时连续相邻这一条已由条头清单落实——关键帧在清单里连排、不与资产图穿插，K 到 M 本就是一段连号，不必再写进生成框对模型说。哪一帧管哪一段、哪一镜，落到正文对应位置才二次点名：A 轨在它管辖的那一段段内写「本段构图与站位以 @图片6 为准」，B 轨在对应镜头行内写「本镜构图以 @图片6 为准」。这是唯一允许二次 @ 的资产类型，且只许点在它管辖的那一段/那一镜里——把整串关键帧连同各自时间点堆进绑定块单行，是把「一次绑定」写成三到六次重复的典型翻车，不算合法二次 @。
        - 站位图：@图片N 仅作为人物站位与朝向参考（POSITION REFERENCE ONLY）；风格、光线、质感全部来自场景与角色参考；不得把图上的线条、色块与网格渲进画面。末半句是防渗句，一次都不能省——正向的「除位置外不从本参考取用任何内容」压不住线稿的网格与哑色块，那是站位图最经典的废镜形态；它属技术性设定的内联否定，不占第 7 段 ≤3 名额，判据见 references/negative-policy.md。
        - 轨迹图：与站位图同块、沿用站位图句式，只换职责——@图片N 仅提供路径的起点、路径形状、终点与触发拍；图例四要素连同触发时机逐字随块交付，同样不得把虚线、网格与色块渲进画面。
        - 白模：底片是动态视频、走视频轨，翻译成 @视频N——@视频N 仅提供空间动线、机位路径与动作时序；不要照抄白模动作、不得保留白模质感。深度图：@图片N 仅提供前后景层次、体积与比例关系。
        - 宫格整板，次选路线：声明"@图片N 为完整分镜脚本，共包含 N 个连续镜头，每格代表一个完整镜头而非单独的人物或场景"，并叮嘱不得把分格框渲进画面。走正路时宫格底板只作提帧谱系留档，不进绑定块、不进清单。

[作用域限定 · 多参考混用必写]
    每个非全程资产声明生效区间与禁止迁移方式：
        @视频2 只用于 20-25秒关键反击段的动作节奏参考，不得用于其他段落；不要照抄该视频动作，不要只做简单还原，最终画面不能保留其原始质感。
    参考图使用范围双列表，借脸不借图时用：
        参考图仅用于【人脸身份 / 发型 / 指定特征】；不得复制参考图的【原始构图 / 原始姿势 / 原始背景 / 原始画面本身】。

[占位符体系 · 资产缺位时的过渡写法，不进成品]
    上游资产未登记完时，草稿可用占位符标缺口：{{人物资产：角色名}}{{场景资产：场景名}}{{道具资产：道具名}}{{控制图：待生成}}{{桥接帧：上一条落幅}}。
    铁律：绝不为不存在的资产发号——占位符只活在草稿里，成品落盘前必须换成两件配套的东西：条头清单里一行真实登记的项目编号，与正文里它对应的 @图片N。换不成 = 依赖检测不过，回上游补登记。

[数量预算]
    2.5 输入上限：图片单次 ≤30 张、视频 ≤10 段且总时长 ≤30s、音频 ≤10 段——是天花板不是稳定区。
    稳定区经验值，待实测校准：单条主体 1–5 个最稳；参考视频 ≤20s 最稳；同一角色只绑一张主参考——多张脸照引发换脸；实战预算参考：每条 9 图 + 3 视频 + 3 音频以内最稳。预算决定一条能装几个具名角色：装不下就减员或拆条，回上游改，不硬塞。条头清单末行的上传顺序号就是本条张数，数它即可，不必回头数绑定段。
    认错长什么样：
        "多多益善"式把全项目资产全挂上——每多一份无职责参考就多一路污染源；同角色挂三张不同角度的脸——换脸；把风格图当资产绑——风格靠恒定层的通用基准段文字，不靠图。
