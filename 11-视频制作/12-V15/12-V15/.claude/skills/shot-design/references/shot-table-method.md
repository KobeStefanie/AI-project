[定位]
    排镜落卡时的判据库，不是流程脚本。流程在 SKILL.md 各功能块；这里回答"每一项怎么写才算对、写错长什么样、好的长什么样"。
    落卡时按字段查对应节；从条排镜翻 [排镜方法 · 从条到镜]；定控制等级翻 [判据卡 · 控制等级四档判定]；反推资产翻 [资产需求反推法]；给用户过表翻 [过表呈现格式]。

[分镜卡十项总览]
    每镜一张卡 = 六字段 + 四附加字段。六字段管"这一镜是什么"，四附加管"为什么这么拍、怎么交棒、要不要控制图"。
    六字段：1 镜号与小标题；2 画面内容；3 台词与声音；4 镜头语言；5 时长与节奏；6 光影氛围。
    附加四字段：7 导演意图，物理指令 + 情感解析成对；8 结束状态，条末镜全五字段；9 衔接，切法 + 咬合；10 控制等级 L1–L4。
    这套卡的来源：材料组管 2、3 两项，导演组管 7，镜头组管 4、5、6，剪辑组管 9——四组信息一张卡收齐，从卡到提示词几乎是机械的；空洞——没有目标的镜、没有任务的人物、没有资产的场景——在花掉生成之前就暴露在表上。
    编号规则：镜地址 = 集-场-条-镜，全写 ep01-P03-Cut2-镜1；表内简写"条 2 镜 1"。镜号连续不跳号、不复用；过表改镜不改号；插镜用 镜2a，与拆解插条 c2a 同法。
    简写许可两条：条内非末镜的结束状态降格为"落幅一句"；松档条只落 2–3 镜骨架，编译走因果链 + 镜头自由度边界，景别机位的自由度留给编译。松档条只有三种——UGC 或生活流片型的条、要多 take 选优的条、导演在场阐述里明确放权的条，正片一律不走松档。骨架这 2–3 镜就是该条的定稿镜数：编译只在这几镜内放宽景别与机位，不增删镜——放宽的是怎么拍，不是拍几个。不是每场都要排到牙齿，把生活流排成走位机器人是排镜事故。

[判据卡 · 镜号与小标题]
    怎么认：
        小标题一句话说清这镜的戏剧功能，不是画面复述——"压价""夺表""回头一眼"。
    认错长什么样：
        小标题写成景别，"中景"不是功能；或写成剧情梗概半句，如"他们继续争执"。
    典型例子：
        条 1 镜 3 · 压价。

[判据卡 · 画面内容]
    怎么认：
        在场人物点名分两种，谁在画里谁上卡：reference-index 已登记的用 @编号 + 短串——短串照索引逐字取，表内可并写人名给人认，如 @char-001 陈默（灰布长衫的年轻人）；状态变体写 @char-001-v2 湿身版。本场新增、设计站还没发号的写"名字（拟编号待登记）"，如"伙计（拟编号待登记）"，登记后回填真编号——自拟一个 char-003 占号，设计站分到别的号就是死引用。
        动作 1–3 句、动词领头、穷尽到部位与次数：哪只手、碰哪里、第几下、哪个部位先动。
        道具写明在谁手里、什么状态——持有权是连续性的生命线。
        群演不点名：写死外观与身体块面，如"挤在柜台外的三个布衣身影，前景一条搭着包袱的手臂"，不写人数——超过十几人的人群会塌缩成三五个人形，人数本身不可控。
        单镜内主体 1–5 个最稳，官方稳定性经验值、待实测校准；超了先想拆镜或降主体，不硬塞。条级同样封顶：整条具名主体合计 ≤5，master shot 新入画的人、插入镜新出现的手与物一并计入——排完镜回数一次，超了降主体或拆镜，并与拆解的条级主体预算名单对齐。
        复杂动作不放中段，开场即中态："he is ALREADY mid-swing, the door ALREADY cracking."（他已经在挥棒中段、门已经在裂开。）接近与预备过程另拆一镜。
        状态链不写过渡：States, not transitions（写状态，不写过渡）——模型演不了过渡、演得了状态。"探进包里、掏出、扬手"拆成逐拍状态，不写"从包里掏出并扬起"一笔带过。
    认错长什么样：
        写"两人争执"——没有部位没有次数 = 模型自由发挥；道具没写在谁手里——下一镜道具瞬移之源；群演写"十几个人围观"；把三个无关动作用"并且"串在一镜——并列无关动作 = 两镜起。
    典型例子：
        见 examples/shot-table-example.md 条 2 镜 3——脱手滑行 + 扑捞，穷尽到指尖与表链。

[判据卡 · 台词与声音]
    怎么认：
        台词逐字引号直写 + 一词语气标注：（压着声）"三十五。救急的钱，沈掌柜。"
        本镜可听见的声音各记一笔：音效绑在可见动作上，如表链磕在玻璃柜面的脆响；环境声一层，如夜雨隔窗；BGM 有无。声音四要素的成文语法归 motion-compile 的 sound-writing 工艺，表层只记"有什么、绑在哪"，不写成文。
        口型纪律前置：要口型的台词控制在短句，约 ≤20 词，且该镜景别给到中景以内、说话人正脸或 3/4 侧——表层就把景别和台词配平，不留给编译去救。
    认错长什么样：
        台词写大意不逐字——编译时二次创作 = 台词漂；音效悬空不绑动作，如"紧张的音效"；一镜塞两人交叉抢话还都要口型——改反打或舍口型。
    典型例子：
        镜头语言"近景 · 正面微仰"配台词（喉头发紧）"祖上传的。"——景别与口型互相成立。

[判据卡 · 镜头语言]
    怎么认：
        一句话收齐 景别 + 机位 + 运动 + 衔接运镜，词从 camera 工艺取：景别九级、机位方位、运动方式、视场角锚点。
        空间表述用 blocking 语言：frame-left/right、绑板内可见地标；不用 near/beside/"在他左边"——米数与相对方位对模型无意义。
        一镜一主运镜；允许由主体动作驱动的衔接运镜，如随伸臂 → 急推；两个无动机打架的运镜 = 拆镜。
    认错长什么样：
        "电影感运镜"无信息——模型对这类词近乎无响应；"环绕 + 推进 + 上摇"三连是运镜打架；"镜头在他左边"不可定位，改"机位柜台外侧，沈掌柜 frame-right"。
    典型例子：
        过肩近景（越 char-002 右肩），机位柜台外侧，静止；随他抬头轻微上摇衔接。

[判据卡 · 时长与节奏]
    怎么认：
        预估秒数区间 + 节奏紧/中/疏档 + 气口标记——本镜含 hold/留白则写明占多少。
        数字是规划层参考：数拍与换算的真相源在 script-breakdown 的 duration-pacing.md，本表数字是只读副本、不一致以那里为准；时长语境一律默认"待实测校准"。
        A 轨条编译时这些区间落成时间戳；B 轨条成品不写秒数，区间只用于配平条时长预算，条 `min_seconds`–`max_seconds`（读 `.project-config.json.video_model_config`）、场景级容量非必须填满。排完镜必做一次求和：条内各镜时长区间的上沿相加要落回条时长预算，超上沿先减镜或压单镜时长；求和上沿超 `max_seconds` 一律回剧本拆解重拆条——`max_seconds` 是本项目模型的硬上限，在表层硬掰只是把返工推到生成期。
    认错长什么样：
        全条镜均匀 2s 是没做节奏；对白镜时长小于"说完 + 反应停顿"——地板是台词说完后 ≥1.5–2s 反应；把气口当空白砍掉——气口是戏，是占秒的格不是缝；单镜压到 1s 级还塞完整动作，瞬移糊帧风险。
    典型例子：
        约 3–4s · 节奏中档 · 尾部留 1s hold，他盯着表不说话。

[判据卡 · 光影氛围]
    怎么认：
        只写本镜相对基准的增量——光影基调由 visual-style 通用基准段管，编译时逐字进恒定层；表层写"这镜光有什么变化、什么光进来"：柜台绿罩台灯是本镜唯一暖源；门开时街灯冷光切进一条。
        光要有来源即世界内光源、有方位，写法从 lighting 工艺取。无增量写"随基准"。
    认错长什么样：
        每镜重抄一遍全片风格——那是恒定层的活，表会爆炸且两处维护必漂；"氛围压抑"无来源无方向——顶光打进眼窝、百叶窗阴影割在脸上，才是可拍的压抑。
    典型例子：
        绿罩台灯自 frame-right 下方打亮掌柜半张脸，另半张沉在暗部（随基准低照度）。

[判据卡 · 导演意图 · 物理指令 + 情感解析成对]
    怎么认：
        固定两行成对——
        物理：可执行的动作/微表情序列，精确到肌肉与顺序，如眉心蹙起 → 视线移开 → 喉结滚动一次 → 指节收紧。
        情感：括号体解释这串物理背后的潜台词与人物任务，如：这是"我就知道是这样"的强笑；任务：不让掌柜看出他急。
        情感行必含人物任务，任务写成对具体对象的动词，如压价、逼他让步、藏住急，不写状态词——"感到愤怒"不是任务，"逼他认错"才是。有戏剧变化的镜标出起点到终点，如从试探到摊牌。
        情绪风险高的镜——哭、笑、怒、大表情——在情感行加双向夹钳预留：写明情绪落在哪两个极端之间，如"在克制与崩溃之间；嚎啕 = 过、面无表情 = 不足"，编译时 motion-compile 据此落锁——单词情绪会漫画化，只有夹住两头才稳。
    认错长什么样：
        只有物理无情感——模型把动作演成体操；只有情感无物理——"演出不舍" = 模型即兴的浅表结果；情绪单词裸奔，如"愤怒"；任务写成导演愿望，如"这镜要有张力"。
    典型例子：
        物理：接过怀表，拇指腹沿表盖划过一圈，翻手看底，单侧眉挑起半拍又落回，开口前先把表放回绒布。
        情感：（挑眉是看出货真，放回是不让对方看出——任务：把四十压到三十。）

[判据卡 · 结束状态五字段]
    怎么认：
        条末镜必填全五字段：位置——在空间哪里，绑地标；朝向——身体朝向与视线，两者分开写；持物——双手各有什么，含"空"；动作动势——正在做什么、动到哪、动量落没落地；情绪——一词 + 方向。
        这五字段就是 motion-compile 该条【结束状态】段的直接来源，一个字段不许缺；条内非末镜写"落幅一句"简式：谁在哪、动到哪。
        与接缝卡对咬：拆解接缝卡标了出点手法，动势必须配合——动作匹配剪的缝禁落地停死，留约 0.5s 余势带出；段落收尾/峰值落地的缝要停稳 1.5–3s；落地 ≠ 切黑，仍留视线/因果/声音钩子。
    认错长什么样：
        终态开放——"他动了一下"不是终态，"走到画面右端停步"才是；漏持物——怀表在谁手里没写 = 下一条道具瞬移；朝向只写身体不写视线——视线是下一条首帧的钩子；情绪写成长句抒情——一词 + 方向即可："决绝，底下压着酸"。
    典型例子：
        位置：柜台外一步，背抵门框侧柱｜朝向：身体朝门，视线回投柜台｜持物：右手攥怀表抵胸口，左手空｜动势：推门推到一半，门铃已响，动量未落｜情绪：决绝，向酸楚倾斜。
        这就是 motion-compile 编下一条承接段时逐字要用的内容。

[判据卡 · 衔接]
    怎么认：
        镜间字段——本镜到下一镜怎么切 + 为什么咬得住；条间的缝归拆解接缝卡，本字段不管。
        切法从条内切型枚举取：HARD CUT（硬切）/SMASH CUT（猛切）/MATCH CUT（匹配剪）/INSERT（插入镜）/REVERSE（反打）/WHIP CUT（甩切）。条内不用叠化、淡入淡出类软转场——那是条间、段落级手法，归接缝卡与编译衔接段；官方转场词汇表与三段式切镜公式归 motion-compile 的 transition-vocab，表层只填切法名。
        咬合理由一笔：视线，如他看向门 → 下一镜门；因果，如扬手 → 打上；声音，如先闻铃后见门；图形匹配；银幕方向。
        条末镜的衔接写"交接缝卡"+ 出点方式。
    认错长什么样：
        衔接字段空着 = 把剪辑交给模型；条内标"叠化"——软转场进条内会被渲成半透明鬼影段；咬合无理由——切得动但接不住。
    典型例子：
        REVERSE 反打回 char-001；咬合：上镜尾他视线抬向掌柜。

[判据卡 · 控制等级四档判定]
    控制等级回答一件事：这一镜要不要控制图、要哪一类。等级是路由信号——本表定档，control-image 站按档位 + 镜头特征定具体类型、张数与母版，关键帧序列、宫格、站位图、深度白模的细选归它。
    四档：
        L1 纯提示词：提示词 + 资产绑定即可稳。判据：主体 ≤2、动作简单、空间关系可用 blocking 语言锁死、构图无精确要求。默认档——从 L4 往下排除，排不进高档就是 L1。
        L2 关键帧锚定：构图/身份/起止落点必须钉死。判据：开场定调镜、高光动作的起点或落点须精确、构图即戏——如对称、框中框、身份易漂的远景。主对应类型：关键帧序列，2.5 主流默认。
        L3 走位控制：画面里"谁在哪"本身是戏眼。判据：≥3 人调度、站位交换、走位绑多个地标、master shot。主对应类型：站位图，或宫格批产关键帧。
        L4 空间动线：镜头在空间里怎么走必须精确。判据：穿行/环绕/长运动镜头、精确机位轨迹、复杂遮挡关系。主对应类型：深度图/白模两阶段。
    判定顺序：先问空间——多人调度？镜头动线？ → L3/L4；再问落点——构图或落点要精确？ → L2；都不是 → L1。
    升档信号：该镜返工代价大，一次生成废了很贵；涉事资产一致性历史上不稳；逐帧构图有叙事功能。降档信号：过场镜、松档条、UGC 质感——控制图会杀死随手感。
    认错长什么样：
        全场无脑 L2——每张控制图都是生成成本 + 一致性风险，不是越多越稳；对话正反打标 L4——站位与反打场景板即够；想用站位图锁十几人群演的人数——人群是一个资产，写身体块面不写人数；给 vlog 条上 L4——把生活流拍成走位机器人。
    典型例子：
        当铺场——master shot 镜标 L3，三人 + 柜台地标；夺表镜标 L2，怀表脱手轨迹落点要钉；对白反打镜全 L1；全场无 L4。

[排镜方法 · 从条到镜]
    怎么认：
        按步骤排。
        1. 读该条拆解：节奏档、时长档、讲戏散文；高光条有【逐拍骨架】——排镜 = 把拍聚合成镜，一镜 = 一条有因果顺承的连击链，不逐拍一镜。
        2. 按戏选镜数：
            动作条，默认 10–22s 档、待实测校准，照骨架聚合，常见 4–6 镜；更密的狂剪必须是拆解已显式标注的"刻意"，本站照标不新增。
            对白条，默认 8–15s 档，按回合排：一回合 = 一次「说—应」往返 ≈ 正反两镜，插入镜——道具、手部、反应——按需 +1；一条装 1–2 回合是常态。
            情绪条，默认 8–15s 档，宁少勿多：单长镜或 2 镜，反应 hold 即内容。
            蒙太奇条一格一镜，照拆解子镜清单计数。
        3. 一镜一节拍按戏分档，边界判据：
            简单/安静档：one main action（一个物理动作）、only one camera move（一种运镜）、one dominant lighting cue（一条主导光影线索）。
            动作/高密度档：允许一条因果顺承连击链——奔跑 → 扑 → 夺，是动作戏密度本体、要写满——加主体驱动的衔接运镜。
            两档共禁：并列无关的独立动作、无动机打架的运镜、多要素无理由同变。avoid micro-choreography（避免微观编舞）禁的是无因果堆叠，顺承连击不在此列。
        4. 镜尾与条尾分开处理：条内镜尾靠衔接字段咬合；条尾即末镜走结束状态五字段 + 接缝卡。
    认错长什么样：
        逐拍一镜——骨架 8 拍排 8 镜是碎片，无气口、成本翻倍；对白条排成动作节奏——拿连击链逻辑切文戏；情绪条排 5 镜——把 hold 切碎 = 没有情绪；镜数超过条时长撑得起的密度。
    典型例子：
        见 examples/shot-table-example.md 全场——条 1 对白 6 镜、条 2 动作 4 镜、条 3 情绪 2 镜，同场三形态对照。

[资产需求反推法]
    镜头表落完，从表上反推本场资产需求，输出【本场资产需求】清单——这是编译段的边角资产增量与 scene-design 角度覆盖的直接输入。
    场景角度覆盖：
        汇总本场全部镜头语言字段的机位方向，得出本场场景需要哪些角度板。对话场需全套：3/4 主板 + 正打向 + 反打向 + 每个说话人的背景板；过场/单向场一个 3/4 角度即可。写明哪几镜共用哪个角度。
        此需求登记进 reference-index 的"角度覆盖需求"字段，由 scene-design 消费，含"反打角度从视频拉"的技法判断也归它。
    边角资产：
        本场新出现的配角/次场景/道具逐项对账 reference-index：新增即无记录；复用即有编号直接引；变体记原编号 + 差异，如 @char-001-v2 湿身版。
        核心级新资产如主线人物、贯穿场景 = 拆解遗漏，报主流程回拆解补清单再补做，不入增量清单。
    道具状态：状态即新变体、永不覆盖——"完好怀表"与"表盖磕角怀表"是两个变体；功能道具写状态时序：哪镜前是状态 A、哪镜起是状态 B。
    群演：不入资产清单；在画面内容字段写死外观与块面写法。
    清单四栏：对象，@编号或「名字（拟编号待登记）」｜类型：场景角度/角色/道具/变体｜状态：新增/复用/变体 + 差异｜去向：scene-design/character-design/prop-design 增量补做。
    认错长什么样：
        角度覆盖漏反打——正反打条编译时才发现没有反打板 = 停工；边角资产不对账直接新增——同一间茶馆第二次被从零发明 = 串味；道具状态用备注不开变体——"备注：后面表盖磕角" = 编译时无图可绑。

[过表呈现格式]
    表确认给用户看的是精简投影，不是落盘全卡。
    顺序：1 【场阐述】一段先行 → 2 本场结构一行：几条几镜、轨道建议、总时长预算 → 3 精简表格逐镜 → 4 【本场资产需求】四栏 → 5 一句收口："指镜号改，或点头进编译。方向不对就说「这场重讲」。"
    精简表格七列：镜｜时长｜镜头语言｜画面一句｜台词｜意图一句｜衔接。意图一句 = 情感行的压缩；控制等级/结束状态/光影不进精简表——落盘卡里有，用户要看随时展开单镜全卡。
    改法：用户指镜号，如"镜 3 改俯拍" → 只改该镜全卡 + 联动检查三处：上一镜衔接是否还咬合、条末结束状态是否受影响、资产需求即角度覆盖是否变化 → 重展该镜与受联动的行，不重甩全表。
    "这场重讲" = 例外路径：弃当前表回内部讲戏，重写场阐述再重排；旧表在文件变更记录留痕，不删历史。
    认错长什么样：
        把落盘全卡直接甩进对话——用户被十项字段淹死；用户改一镜就重发全表——找不到改了哪；跳过场阐述直接上表——方向错了逐镜改是白改。
