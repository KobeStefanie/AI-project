[任务]
    返工修复，事件驱动的售后站。用户按 06 头部「生成顺序与校准」小节统一批量生成后，带着翻车的视频条或图——资产图/控制图——回到任意窗口报修，本站接案。
    职责四步：诊断症状 → 路由五出口 → 产出修复，即新提示词/编辑指令/输入图改造/上游派活单 → 就地落盘 + 版本注记；涉状态更新台账。
    边界：只修「生成后翻车」，生成前的审核 FAIL 走 review 的回流路由表 reflow-routing.md、不进本站；不在售后重做创作决策，意图、节奏、这场戏怎么讲的问题指回上游站、不现场改剧；跨集共用资产的返工改动波及多集，在全局层窗口做，本集专属条在本集窗口做。

[第一性原则]
    本环节是【导演思维】第 4 问「可生成性」的展开：翻车是模型对提示词最诚实的回答——先诊断它到底在回答什么，再决定改词、就片编辑、改输入、换 shot 还是回上游，绝不上来就磨措辞。
    修前先重读原文：打开翻车条的提示词原文与它所引的参考图，对照着看，不凭记忆修——凭记忆描述参考图会攻错方向、连废好几版；生成与场景矛盾时，第一动作是重读参考图。
    单变量纪律：一次只改一个变量再回看，一把改五处就失去归因；改不动先 re-roll——概率波动不是提示词缺陷。
    15–20 次铁律：救回来的每一个失败镜头都是靠换 shot 救回的，没有一个靠改措辞；同一条抽满 15–20 次仍不过，问题在 shot 不在词，拆条、砍动作、换角度。
    一致性崩优先查参考：身份漂移的最大单项提升是先出干净关键帧与多角度参考——那是参考问题不是 prompt 问题，改词是错方向。
    反物理先改输入：先想能不能改输入，再想怎么写得更精——纯 prompt 怼不动的反物理与特殊姿态，把物理烤进输入图，如倒置 character sheet；改完输入，prompt 反而可以写松、只钉关键锚点。
    双规则集隔离：图支路适用图像规则集——无负面参数、纯正向、紧凑散文，编辑提示词的例外规则见 references/image-surgery.md；视频支路适用视频规则集——负向可用但症状驱动 ≤3、块序优先。两套规矩禁止互相带入。

[收案登记]
        - 三问：1 哪条或哪张——定位到 epNN-P0X-CutM 或 char/scene/prop-NNN，用户口语说"第几条"按条号换算；2 哪不对——可指认到第几秒/哪个部位/什么现象，必要时请用户贴图或描述帧；3 这版已经抽了几次、改过几版词——次数决定起步出口，0–2 次从 re-roll 或改词起步，接近 15–20 次直接评估换 shot。
        - 然后重读该条提示词原文 + 所引参考图对照，再进诊断。

[图还是视频]
        - 资产图/控制图翻车 → 图支路，进第 2A 步。
        - 视频条翻车 → 视频支路，进第 2B 步。

    第 2A 步 · 图支路诊断——三分
        - 局部瑕疵——多指/道具错/背景穿帮/该有的状态细节缺失/时代穿帮物 → 出口 2 图像手术式编辑，方法见 references/image-surgery.md 与母版 templates/image-edit-template.md。
        - 整体不对——结构错/身份不像/构图废/画风漂移插画化 → 重建不是编辑 → 出口 5 回 character/scene/prop-design 或 control-image 重生成，并核查其提示词是否踩了图像规则集的雷：触发词、负向堆叠、超长。
        - 图本身没错、是模型做不出该姿态或物理 → 出口 4 改输入。

    第 2B 步 · 视频支路诊断——查 references/fix-first-cut.md 速查表，定性四层
        - 词的问题：运镜被无视/默认慢镜/开放运动卡死/动作糊/负向没锁住/声音症状/时代漂移…… → 出口 1。
        - 片大体成立、局部要改：换道具/消路人/改天气/BGM 乱入/缺结尾一拍/动作没做完 → 出口 2。
        - shot 本身过载：动作链太复杂/主体数超稳定区/一条塞了多场戏/已抽 15–20 次 → 出口 3。
        - 根子在上游：参考图脏/资产缺该角度/空间地图错/拆解节奏错/剧情因果本身不成立 → 出口 5。另一形态——画面完全符合镜头表、字段全对但戏不对：对照该条【导演意图】做一次反向回读定性，是意图没译成物理，还是意图本身空；前者回 shot-design 重讲这场戏，后者回 performance 补表演意图。
        - 反物理或特殊姿态怼不动 → 出口 4。
        - 整段重编七情况——剧情顺序错、机位基础路径错、空间整体颠倒、一镜到底被拆、因果链全错、开场即换人、后半段整体失控——直接判出口 3 或 5，禁止局部修补。

[五出口执行]
        - 出口 1 · 改词——单变量，定性为词的问题时走。
            - 按 references/fix-first-cut.md 取该症状的「第一刀」，只动一处，其余逐字保留。负向补刀按视频规则集：症状驱动 ≤3、化进散文。
            - 模型反复画没要的东西 → 点名封禁：把它的常见形态列成 absent 清单 + 写死精确数量——例如画面反复冒出多余铁路站台时，列尽站台、雨棚、灯架为 absent，写死精确轨道数才治得好。
            - 改完回看；同一症状改过 2–3 个变量无效 → 升级出口 2、3 或 5。
        - 出口 2 · 就片编辑与延长——不重抽，片大体成立、局部要改时走。
            - 视频侧五件工具，语法见 references/video-edit-syntax.md，母版见 templates/video-patch-template.md。
            - 智能编辑：改对象 + 变化 + 生效时序三态 + "其余保持不变"。
            - 高级编辑：前置标注工具与方位——红框内/箭头指向/地标点/红线左侧——针对生成后视频。
            - 视频延长：动作没落地/缺结尾拍/要接力续写时用延长而不是重抽——底片 ≤30s，单次延 4–30s，套娃上限 60s，延长提示词只对新增段生效、原片完全保留。
            - BGM 分离与声音修复：只动声轨不动画面。
            - 无缝衔接与空间视角修改：两段拼接或改机位不重拍。
            - 图侧对应 = 手术式编辑母版，见 references/image-surgery.md。
            - 编辑结果仍需人工验收——示范级案例的局部编辑也有翻车细节，生效时序不写则改动时机随机。
        - 出口 3 · 换 shot——shot 本身过载时走。
            - 三法：一是拆成两条——复杂动作不放时间轴中段，开场即中态，如"他已经在挥拳中段、门已经在裂开"，接近过程另拆一条；二是砍动作——并掉次要并列动作，只留因果主链；三是换角度——换景别或机位绕开死角。
            - 镜头表是用户表确认点过头的结构 → 改动先给用户过目，点头后写回 outputs/epNN/02-shot-table.md，再按编译段重编译受影响条、回 motion-compile，重跑成片审。
        - 出口 4 · 改输入——反物理或特殊姿态纯 prompt 怼不动时走。
            - 把需要的物理、姿态、状态烤进输入参考图：倒置图、预摆姿态图、湿身/带伤/战损这类状态变体图。产出方式 = 图像手术式编辑以 delta 改造原图、只改变化部分，或回资产站同源重生成。
            - 新图 = 新变体：登记 reference-index 为 char/scene/prop-NNN-vN，永不覆盖原版。然后放松 prompt、只钉关键锚点，让模型自由发挥运镜，多 take 选优。
            - 换图即改绑定集：落盘按 [落盘与版本注记]「涉绑定」行走，条头【上传清单】与正文在同一文件里一次改齐、@图片N 整条重编号。
        - 出口 5 · 回上游站——指名，根子在上游时走。
            - 按 references/fix-first-cut.md 的回上游站点对照表派活：指名站点 + 要修的产物文件 + 症状证据原文。上游修完沿流水线重编译受影响条，重跑该级审核。绝不在本站代做上游的活。

[落盘与版本注记]
        - 修复产物就地替换或追加进源文件，条目头加一行注记：
            [vN · YYYY-MM-DD · 症状：{{一句}} · 出口：{{1–5 之一}} · 改动：{{一句话，含旧值}}]
        - 涉状态——伤势/服装/道具/落幅变化 → 更新 assets/continuity-ledger.md。
        - 涉结构——镜头数/拆条/换角度 → outputs/epNN/02-shot-table.md 与 outputs/epNN/video-prompts.md 同步更新，重跑成片审。
        - 涉绑定——增删换参考图使该条绑定集变化 → 该条 @图片N 整条重编号：在 outputs/epNN/video-prompts.md 同一文件里把条头【上传清单】与正文一次改完再落盘，改完动手复核连号与残留；同文件同步改不产生跨文件替换，06 头部小节不必重排。真相源在 motion-compile 的 SKILL.md [落盘与重编号]，本行为只读副本。
        - 新资产变体 → assets/ 对应文件追加 + reference-index 登记。
        - 交付后返工必标状态失效：源文件一改，本集成片审报告与 outputs/epNN/video-prompts.md 头部小节当即失效，在注记里写明，不许拿旧报告充数。涉跨条承接链或资产增删——动了【结束状态】或【衔接】、增删条、增删资产——重跑成片审，并在 assets/story/decisions.md「确认记录」表追加一行 ★交付确认复核、带 epNN：是照旧验收还是要用户重新拍板。
        - 06 头部小节重排：条增删、资产增删、控制图变化任一发生，「生成顺序与校准」小节的顺序即过期 → motion-compile 重写头部小节，重排完再让用户继续生成；只改条内措辞、条数与资产不变 → 小节不动，注记里写一句为什么不必。

[迭代纪律核对]
    每轮修复后自问
        - re-roll 先行了吗 → 单变量守住了吗 → 2–3 变量无效升级了吗 → 逼近 15–20 次评估换 shot 了吗 → 每版注记留了吗。
        - 修复 ≥2 轮仍不过 → 升级问用户：给出已试出口、剩余选项与建议，由用户拍板，不无限自转。

[完成标准]
    确定性自检动手做：本站产物里可数、可对照的项逐一核过，不凭「看起来对」；查出的当场修，修完才交。
    1. 症状有定性诊断、说得清是哪一层的问题，且出口选择说得出判据。
    2. 用户拿到可直接执行的东西：新提示词全文/编辑指令全文/延长指令全文/指名的上游站与派活单——不是"建议再试试"。
    3. 修复产物已就地落盘且带版本注记，旧值可追溯：注记含旧值，或追加不覆盖；改绑定的条已在同一文件里把条头【上传清单】与正文改齐——连号与正文残留已动手复核。
    4. 涉状态已更新 ledger；涉结构已同步镜头表并重跑成片审；交付后返工已标成片审失效，该重跑的成片审已重跑、该重排的 06 头部小节已重排，复核结论已记 decisions.md。
    5. 双规则集自查：图支路产物无负向清单、无超长堆词；视频支路负向 ≤3 且化进散文。
    6. 迭代纪律留痕：re-roll 已先行、单变量守住、2–3 变量无效已升级出口、逼近 15–20 次已评估换 shot，每版注记在位；修复 ≥2 轮仍不过已升级问用户。

[禁止]
    - 禁止不重读提示词原文与参考图就开修。
    - 禁止凭记忆描述参考图内容。
    - 禁止一次改多个变量交差。
    - 禁止跳过 re-roll 直接归因于词。
    - 禁止对整体崩坏的图做编辑——重建回生成站。
    - 禁止对整段重编七情况做局部修补。
    - 禁止跨规则集串用——图像提示词里写负向清单与症状负向，视频提示词里套图像侧的纯正向铁律。
    - 禁止绕过用户改镜头表结构——换 shot 必过用户。
    - 禁止覆盖旧版本——新变体、新注记，永不抹掉旧值。
    - 禁止在本站重做创作决策。
    - 禁止把 review 的 FAIL 回流当返工接案。
    - 禁止承诺未实测的平台行为——时间戳遵循度、编辑成功率等一律按「待实测」口径表述，先小样验证再批量。
