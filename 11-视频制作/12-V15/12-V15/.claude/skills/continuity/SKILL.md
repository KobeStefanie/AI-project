[任务]
    维护全片唯一的状态连续性台账 assets/continuity-ledger.md，并为成片审提供连续性批检方法。
    台账回答的问题是"剧情进行到哪、谁现在什么状态"。每条提示词生成时模型无记忆，跨条、跨场、跨集的状态连续全靠显式承接——上一条的结束状态是下一条的输入状态。条与条的承接写在成品里；跨场、跨集、跨窗口的承接就记在这本台账里：窗口可以关，台账不会忘。
    两类活：
        - 场末更新，即编译段的台账步：本场编译完、成片审派审前，把逐条落幅、持久状态变化、场末快照、未解线头登记入账；本集最后一场登记完，更新跨集 ending state 区。retake 修复涉及状态时同步更账。
        - 成片审批检支持：提供逐缝核对表与分组派工方法，在 references/seam-audit.md，成片审按它派批检工人 subagent 逐缝核对继承链。工人用 review skill 执行、只审不改；本 skill 只供方法，不自派审核。
    台账只记事实，不做创作、不改成品：登记中发现状态对不上，交回主流程走修复，不悄悄抹平。

[第一性原则]
    本环节是【导演思维】第 3 问「一致性」的展开：五源对账里"剧情走到哪、谁现在什么状态"这一源由台账唯一供给——查文件，不凭记忆。
    状态机三层同构：连续性状态机有三层落位，粒度不同、字段对齐：1 成品内——每条【结束状态】五字段，即位置、朝向、持物、动作动势、情绪，管条与条的显式承接；2 编译推理——motion-compile 编译时逐镜追踪的内部状态，用完即弃；3 台账——跨场跨集的持久化层，管窗口关掉之后的记忆。本 skill 管第 3 层。第 1 层写坏了是编译缺陷，回 motion-compile 修，不在台账里将错就错。
    落幅照录，不改写：逐条落幅从成品【结束状态】原文照录——台账是成品的账本投影，一个字的"润色"就是第二真相源。账实不符 = 缺陷，成品错或账错，报出来修源头，不静默对齐。
    变化才记：五字段逐条必录；扩展状态只在发生持久变化的当条记一行，含伤损、服装污损、持物转移、场景破坏、时间天气光线。瞬时状态不入账，含表情呼吸阶段、机位焦点、声音延续——它们活在条内，由成品【衔接】段与下条承接管。台账膨胀比缺记录更危险：翻不动的台账等于没有台账。
    任务进度守恒：已完成的动作不得重新开始；已处理的物体不得恢复到未处理状态；人物位置和道具位置不得无原因重置。这三条既是登记时的扫描项，也是逐缝审计的固定检查项。
    状态即新资产：角色/道具的持久外观变化——受伤、换装、损毁——对应 reference-index 的变体条目：-vN，新状态 = 新变体，永不覆盖。台账记"何时变的、剧情为什么变"，索引记"变成什么样、用哪张图"——两边都要有，缺一边就是登记缺口。
    线头必收口：未解线头——带伤未愈、道具遗留、悬置的时间跳跃——要么后续场关闭并记关闭位置，要么集末显式移交下一集，不许无声蒸发。跨集穿帮多数死在"上一集忘了自己留过什么"。
    永不回改：台账追加式更新——登记错了走变更记录追加更正行，不静默覆盖历史；成片审对账要能看到轨迹。

[场末更新法]
    编译段每场编译后执行，八件事按序：
    - 首建判定——assets/continuity-ledger.md 不存在 → 按 templates/ledger-template.md 建骨架；开场初始状态从 outputs/epNN/01-director-analysis.md 讲戏本的开场设定取——人物初始位置/服装/持物、剧情起始时间，登记为"开账基线"。

    - 读原文——本剧情点 video-prompts.md 内逐条【结束状态】与【衔接】、镜头表逐镜结束状态、台账上一场落幅。全部读盘上原文，不凭编译时的窗口记忆。

    - 逐条落幅登记——从每条成品的【结束状态】五字段逐字照录进台账：条号 + 五字段原文照抄，不改写不转述；再手写三段——状态变化、场末快照、未解线头。

    - 持久变化扫描——对照 references/state-machine-12.md 的持久类维度扫本场成品正文：伤损、服装、持物转移、场景破坏、时间光线推进。有变化的记入"状态变化"块——谁 / 什么变化 / 发生在哪条哪镜 / 此后是否持续可见。涉及角色/道具外观的，核对 reference-index 是否已有对应变体 -vN；缺 → 交回主流程走资产变体登记，派 character/scene/prop-design，不代劳登记资产。

    - 场末快照——每个出场角色一行：位置、服装含污损、伤势、持物、情绪落点；另记道具位置 + 场景状态 + 时间线位置。快照是下一场编译的直接输入——motion-compile 下一场首条承接的就是它。

    - 线头登记——新增未解线头标 [开]；本场回收了此前线头的，改标 [关闭于 epNN-P0X]，原行保留。

    - 一致性冲突上报——登记中发现条间承接断裂即下条开头与上条落幅对不上、成品与镜头表结束状态不符、状态与变体引用不符——不改成品、不改镜头表，向主流程报缺陷，给条号 + 原文证据一句，由你派修，或挂账到成片审一并处理。

    - 集末更新——本集最后一场登记完，更新"跨集 ending state 区"：主要角色最终落幅、关键道具下落、世界状态、时间线位置、移交线头清单。下一集窗口的开场协议读的就是这一区。

[retake 联动法]
    retake 修复涉及状态时执行：
        - retake 修复改了某条结束状态、伤势时序或道具下落时，就地更新对应落幅行与场末快照，并在变更记录追加一行——日期 / 触发 / 改动 / 下游影响提醒，受影响的后续条列名，只提醒不自动改。

[成片审批检支持法]
    成片审到点时执行：
        - 把 references/seam-audit.md 交给成片审主审与批检工人使用——缝的枚举法、分组派工规则、工人上下文契约、逐缝核对表、证据写法全在该文件。工人的发现清单汇入成片审报告；缺陷按 review 的回流路由表派修——其中"台账登记错误"一类回本 skill 修账，走变更记录，不抹历史。

[结构化结果]
    每次场末更新完成后交一份报告回主流程；对话内交付，不落独立报告文件：
        - 登记范围：epNN-P0X，N 条落幅已入账。
        - 状态变化：M 项，逐项一句：谁 / 什么变化 / 发生在哪条。
        - 线头：新增 x 项 / 关闭 y 项 / 当前在开 z 项。
        - 对账结果：五字段承接链逐缝自查通过；或发现缺陷 k 处，给条号 + 一句证据，已报回主流程。
        - 集末另附：跨集 ending state 区已更新，移交线头 n 项。
    这份报告是台账步的完成凭证；台账本身则是成片审逐缝批检与下一场/下一集编译的对账依据。
