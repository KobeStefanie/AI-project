# 审核共享方法论（v14 · 查病制）

> 4 个审核 skill（`script-analysis-review-skill` / `art-direction-review-skill` / `seedance-prompt-review-skill` / `compliance-review-skill`）共用的**审核哲学、五类病定义、判定规则、报告格式**。
> 各 skill 自身只保留「**审核对象**」「**只读基准**」「**本级查什么**（专属检查项）」，其余引用本文。
> CLAUDE.md [审核工作流] 是本方法论的编排层入口；本文是执行细则。
>
> 📌 **源库站名映射**（回流路由表沿用了 Seedance 分镜师 3.0 的旧站名，**均不是真实存在的 skill 名，别去调它们**）：`motion-compile` = `seedance-storyboard-skill`（分镜师编译段）· `script-breakdown` = 导演拆解（`outputs/epNN/01-director-analysis.md`）· `character-design` / `scene-design` / `prop-design` = `art-design-skill`（服化道）· `control-image` = 控制图，V14 无独立站、分镜师兼做落 `outputs/epNN/control-prompts.md` · `director-grill` = `director-skill`。

## 一、审核立场（最重要的一条）

审核 = **交货质检，不是站岗门禁**。你的任务是**在交给用户前找出会翻车的病**，不是确认通过、更不是评价品味。

- **找病不确认**：以"挑刺"的心态读，不为不完美找借口。
- **不做工艺品味、不提「可以更好」**：风格好不好、决策对不对，是用户在确认时自己看的事，不是审核该管的。审核只回答"这东西拿去生成/发布，会不会翻车"。
- **审核员的唯一优势是新鲜眼睛 + 跨文档对照**：所以只查五类病，别越界替创作者做判断。

**自检小问**：你写的每条发现，能不能让上游 agent 不追问就动手改？不能 → 你没写清楚。

---

## 二、五类病（全库唯一的审核维度）

审核只查这五类，别的一律不判：

1. **矛盾** — 同一事实在被审产物内两处互斥：声明与预算打架、同一物两个尺度、基准段与字段表相反、恒定层跨条不一致、缝两端结束状态对不上、任务进度回退。
2. **断链** — 指向不存在或对不上的东西：死引用、编号跳号、登记与包不双向对齐、注记指不到落点、下游动手缺信息（自包含破洞）、变体在 reference-index 查无。
3. **走样** — 产物对**只读基准**的翻译悄悄偏了：场漏拆、台词不逐字、基准段未嵌入或不同源、镜头表与讲戏本对不上、成品与镜头表对不上、资产三态与剧情进度不符。**带显式声明的偏离（狂剪标注、偏离理由）不算走样。**
4. **模型雷** — 已知让生成翻车的写法，脑内预演命中：抽象情绪词、互斥动作叠加、开放运动无终点、口型违规、弱空间词、图像规则串进视频侧（或反之）、负向 kitchen-sink、气口被挤没、时代锚缺失、@tag 重复。
5. **红线** — 合规布尔判定，照 `compliance-review-skill` 的 12 类：真人肖像、版权 IP、政治敏感、色情/暴力尺度等。成片审另查**跨条组合风险**——单条无害、连起来构成教程或侵权叙事的按组合判。

## 三、判定规则（取代旧评分门槛）

### 只有 blocking 挡线

**blocking 白名单**（名单外一律不判 blocking）：
- 断链类的**死引用**
- 矛盾类的**同一资产双真相源**（锚定资产双重发明、一条多脸源）、**缝两端状态互斥**、**@图片N 与条头清单对不上**
- 模型雷类的**规划类控制图（站位图/白盒/深度图）被绑成画面参考**
- 红线任一 🔴

判定分档：
- **有 blocking → FAIL**：按 [回流路由] 修 blocking 项 → **靶向重审**（只核销上轮 blocking 项与其修复处，不重头审）。
- **major / minor 修而不挡**：全部进派活清单，修完**不重审**，随产物交用户确认时报「审核发现 N 条、已修」。major 与 minor 只差派活优先级，不差是否挡线。

### 一轮为限 + 熔断

- 靶向重审只有一轮。重审轮里新冒的发现按严重度归位（blocking 改判定、其余进派活清单），**不另起第三轮**。
- 同一审核点**连续两轮 FAIL**、或对判据本身有分歧 → 停下，把两轮报告与分歧摆给**制片人转交用户裁决**，不自转下去。

### PASS 后

- PASS 后被审产物无改动 → 不重审、不设时效追踪。
- 改了已审产物（你改的或用户要的）→ 旧报告作废，**重审该对象一次**。
- 多处坏时停在**最早坏阶段**，先修上游——上游改了下游基准就变了。

---

## 四、阶段门：先查便宜的三类

先查**矛盾 / 断链 / 走样**——纯文档对照，不花预演成本。命中 blocking 即交报告，模型雷预演**不跑**——烂地基不评精装修。前三类干净了，才做模型雷预演与红线判定。

**对账动手做**：编号连不连号、台词逐不逐字、时长求和超不超、基准段能不能 diff——**数出来、diff 出来**，不凭"看起来一致"下结论。

---

## 五、只读基准原则

**已确认的上游产物是尺子，永远不是病人。**

- 产物与基准对不上 = 产物走样，判产物。
- 怀疑尺子本身坏了（已确认文档内部矛盾、两份基准没同步、判据与现实打架）→ 写进报告尾部「上游观察」小节：一条一行，**不算发现、无严重度、不派活、不影响判定**。由制片人随下一个 ★确认 一并呈用户裁决——重开上游是用户的权力，不是审核的。

---

## 六、防误杀（判回前必过）

判回一条标杆写法、和放过一个真缺陷，**同罪**。判回前自问：

- **这是设计还是断裂**？场间时间跳跃、情绪转折、景别跳切都可以是剪辑设计——**有声明即合法**，只抓"该交代而没交代"。查的是「无因跳变」，**不是「必须相同」**。
- **松档条的自由度边界内不判**：松档声明了"景别机位剪辑可自然变化"，机位类差异不命中；但"因果顺序与动作结果不得变化"仍是硬线。
- **可跟随性高于完备性**：能被模型照着生成才算好。别因为"不够详尽"判回一条其实模型跟得住的干净写法。
- 合规拿不准 → WebSearch 核实，不靠记忆里的旧红线。

## 七、报告格式（人读，落盘 `outputs/<集>/review/<级别>-report.md`）

一页起步。每条发现七字段，与 `continuity/references/seam-audit.md` 的 finding 同构：

| 字段 | 内容 |
|------|------|
| **类** | 矛盾 / 断链 / 走样 / 模型雷 / 红线 五选一 |
| **定位符** | 精确到条/镜/字段，如 `ep01-P03-Cut2 分镜正文` / `人物设计 > 林书白` / 缝记两端条号 `ep01-P02-Cut2 → c03` |
| **原文证据** | 直引原文，**不转述**；矛盾/缝类引两端原句 |
| **严重度** | blocking（白名单项）/ major / minor |
| **回哪修** | 按 [回流路由] |
| **改向** | 可执行一句，写清改哪里、改成什么——避免"加强叙事"这种空话 |

报告结构：

```markdown
# ep0N <级别>审核报告

**总判定**：PASS ✅ / FAIL ❌（有 blocking）
**问题计数**：blocking N｜major N｜minor N
**最重的一条**：<一句话>

## blocking（挡线，必修后靶向重审）
### #1 · 类 · 定位符
- 证据：<原文直引>
- 回哪修：<站>
- 改向：<可执行一句>

## major / minor（修而不挡，修完随产物交确认）
### #2 · 类 · 定位符 · 严重度
- 证据 / 回哪修 / 改向

## 上游观察（不派活，随下一个确认呈用户）
- <一条一行>
```

**发现描述的好坏对照**：

| ❌ 不合格 | ✅ 合格 |
|------|------|
| "P03 镜头不好" | "ep01-P03-Cut2 分镜正文要求镜头同时推到面部、环绕走位、固定机位——三个运动互斥（模型雷）。改向：保留推镜+环绕之一，或拆两镜" |
| "颜色不对" | "服化道 林书白 内搭写'红色衬衫'，与 character-profiles 里'刻意低调'矛盾（走样）。改向：改'深灰立领针织衫'" |

核心：**判定与放行归制片人**，审核只出报告；结论与证据都在报告里。

## 八、回流路由（默认规则）

每条发现回**被审产物的生产站**修：

| 审核点 | 回流到 |
|--------|--------|
| 拆解审 | 导演（script-analysis-review 发现）；visual-style 定稿增量与 reference-index 骨架同回导演 |
| 资产审 | 服化道（art-direction-review 发现） |
| 音乐审 | 音乐总监（reviewer 直审发现） |
| 镜头表审 | 分镜师第一步（shot-design / 镜头表阶段） |
| 成片审 | 分镜师第二步（编译阶段） |
| 台账账错 | continuity（由分镜师修账）；账实两处都错各记一条，实错回 motion-compile |
| 变体缺失 | 对应设计站（角色→服化道等） |
| 结构性矛盾（镜头数/切点/剧情顺序） | 分镜师第一步（镜头表）或更上游导演 |

默认之外的少数特殊路由见各 skill 或 `seedance-prompt-review-skill` 的成片审段。用户在确认时提的修改，改完即交、不另审（除非改动触发"改了已审产物"规则）。

## 九、受众适配（走样类的一个检查维度）

对照 `assets/story/script-settings.md` 的「目标平台」与「目标受众画像」两段（**按字段名找，不按项号**），做"目标受众看到会不会中段划走 / 会不会想分享"的脑内预演。产出与目标平台规律（见 `_shared/audience-engagement-guide.md` 第三节）明显脱节 → 按**走样**记一条 major，改向写清哪里不合该平台逻辑。

- 有对标爆款（`script-settings > 对标爆款` 状态为"有对标/推荐后认领"）→ 附查"气质是否同频"（不是形似；镜头台词雷同但气质偏离 → 记抄袭风险）。
- 状态"无（用户主动声明）"→ 跳过对标，只看平台规律。
- 字段缺失 → 记「上游观察」要求补全，不凭空判。
- 院线/影展项目 → 换标准（艺术性高于平台规则），受众看评委/影评人。

受众适配**不是独立评分**，是走样类下的一个检查角度；命中才记，不命中不写。

---

## 十、技术约束底线

判"X 应该保证 Y"类问题前，先核 `_shared/ai-generation-constraints.md`：别要求上游产出 AI 技术上做不到的东西（如视频跨段帧对齐）。明确区分"描述层面的呼应"（可审）与"生成结果的像素级对齐"（不可审、技术不可达）——后者出现在成片审的连续性检查里，靠 `continuity/references/seam-audit.md` 的缝审计，查的是文字状态承接、不是帧。

---

## 十一、质量分的去处

审核**不再产出评分、不以分数作放行门槛**。放行只看 blocking。
唯一的评分出现在**分镜全 PASS 后 reviewer 写的 `00-quality-report.md`**——那是给用户的整片复盘参考分，不回流、不挡任何东西。格式见 `agents/reviewer.md` [质量综合报告]。
