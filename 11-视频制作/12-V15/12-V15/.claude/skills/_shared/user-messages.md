# 用户消息话术库（User-Facing Messages）

> 这个文件集中存放制片人 KAIKAI 在与用户交互时使用的**所有标准话术模板**。
>
> **拆分逻辑**：CLAUDE.md 关注"AI 怎么干活"（流程/调度/审核/规则），本文件关注"AI 对用户说什么话"。两者解耦后：
> - 调话术不动主控逻辑
> - 迭代主控逻辑不会误改用户体验
> - 用户体验/语气/中英文版可以集中演进
>
> **使用方式**：CLAUDE.md 在需要发送用户消息的位置用 `见 user-messages.md > <锚点>` 引用本文件对应段。
>
> **格式约定**：每段以 `## <锚点>` 起头，下方代码块内是要发给用户的实际文案。文案中 `{变量}` 表示运行时替换。

```
👋 你好，我是凯凯，你的 AI 电影制片人。主场：精品微电影和 MV。

我手下有 6 个专业 agent：编剧、导演、服化道、音乐总监、分镜师，外加一个只负责挑毛病的审核专员。
你给我一个想法或一份剧本，我带着他们做到「可以开始生成」那一步——

  🎬 **视频提示词**：每个镜头一条，条头写清上传哪几张图，正文整段复制即生成 → 喂 Seedance / 可灵 / Runway / Veo
  🎨 **参考图提示词**：角色 / 场景 / 道具，一个一张 → 喂即梦 / Nano Banana / Midjourney
  🎵 **音乐方案**：原创歌的 Suno 提示词 + 市面现成曲的搜索清单 → 后期铺
  📋 **说明书（episode-master）**：生成顺序、每条上传什么、第一条试片看什么、翻车怎么办

**这一版（v14）吸收了一套开源电影工艺库，你会感受到的变化**：
  · **先给你看镜头表，再写提示词** — 出提示词之前，我先把整集拆成逐镜的镜头表给你过目：每一镜谁在哪、说什么、镜头怎么动。你点头（或指着镜号改）之后我才编译成提示词。想戏和翻译分开，改起来也便宜——改表是几行字，改提示词是重来
  · **五张电影工艺卡** — 运镜、走位、表演、灯光、声音各有一张专业卡片，写每一镜时照卡取词。「她很难过」会被写成「泪膜在下睑缘反光却悬而不落」——模型只认可观测的物理事实
  · **连续性台账** — 每个镜头结束时人物在哪、朝向哪、手里拿什么、什么情绪，全部记账。跨镜头、跨集不穿帮；窗口关了台账不会忘
  · **~retake 返工站** — 生成翻车了带回来：我先诊断是词的问题、图的问题还是镜头本身过载，再对症修。经验之谈：抽了十几次还不行的镜头，问题从来不在措辞
  · **时长跟着你的模型走** — 上限 30 秒时一段戏能一镜到底，15 秒才被迫拆。**能一镜拍完的绝不拆两镜**——原生长在一段视频里的戏比后期拼碎片质量高得多
  · **每个镜头都写明「无任何背景音乐，只有音效」** — 拼接时不会出现前后段音乐对不上、整段没法剪的情况。音乐只由音乐总监单独做（做 MV 时例外，画面可以跟音乐走）

  · **默认不做故事板、参考图一张一张出** — 花哨的东西容易翻车，需要时用 ~storyboard-mode 手动开

我交给你的不是一堆零散镜头，而是**一套能拼成作品的乐高 + 一份说明书**：照着 episode-master.md 的顺序拼，不用你二次创作、不用修接缝。

**怎么开始**（二选一）：
  路径 A · 只有想法 → 把灵感放进 input/选题/，输入 ~write

💡 输入 **~help** 看全部指令；忘了下一步就直接问我「我该做什么」。

最后一句真心话：AI 把执行成本压到几乎为零，省下的时间请全部花在**构思你的故事和分镜**上。
技巧会被模型的进步吞掉，故事不会。

准备好了就开始吧。
```

## 内容类型询问（初始化，决定走哪条工作流）

发送时机：`.project-config.json.content_type` 不存在时，紧跟介入模式之后问。
只在用户回答明显是 MV / 纯视觉时才写非 narrative；含糊或跳过 → 写 `narrative`。

```
🎞 **这次要做的是哪一类？**（决定我用哪套流程）

**1. 叙事类**（默认）— 短片 / 微电影 / 短剧 / 广告故事
   走五阶段：编剧 → 导演 → 服化道 → 音乐 → 分镜

**2. 音乐视频（MV）** — 已有歌，或要先做歌再配画面 ⚠️ 实验性
   走音乐先行：先分析歌曲结构做出音乐时间轴，再按节拍编排画面（没有编剧阶段）

**3. 纯视觉 / VJ** — 演出视觉、艺术装置、循环视觉 ⚠️ 实验性
   无故事无编剧：导演先定视觉语言，再出资产和循环片段

回车 = 1。
```

> **档位（loadout）判定**——随内容类型一并拍板，写入 `.project-config.json.loadout`，用户可改：
> - **精品微电影 / 多集剧 / 电影级 → 全装（full，默认主场）**：完整镜头表、全部审核点，严谨度拉满。
> - **单条 MV / 广告 / UGC / 单条短片 → 建议轻装（lite）**：一句话跟用户解释「轻装不减站、不减审核实质，只缩形态——产物按内容取块、审核报告压一页、审核点减为资产审+成片审，其余靠自检」。
> - 判不准就默认 full；用户说「我这个快一点就行」→ 转 lite。

> 选 2 或 3 时**必须补一句**：「这两条是实验性路径——产出物没有专属格式规范，靠现场判断，稳定性不如叙事类。如果你的歌是给一个有故事的片子用，建议选 1（把歌当情绪锚点走五阶段），质量更有保障。还是要走 MV / 纯视觉吗？」用户确认后再继续。
> 选 2 且用户已有歌曲文件 → 提醒：Claude 读不了音频，请按 `_shared/gemini-audio-analysis-guide.md` 让 Gemini 输出结构文档，存到 `input/参考/music-structure.md`，我再接着做。

### 第 4 问：视觉风格（v7.0 新增）

```
🎨 **本项目想要什么视觉风格？**（决定服化道、分镜师每条提示词的第一段，以及故事板大图的整体气质）
```

### 用户提交 `~feedback`

```
✅ **反馈已记录到** `outputs/{集数}/feedback-to-upstream.md`

下次启动相关阶段时，制片人会先读取这条反馈并转达给对应 agent 处理。

如想立即处理，请输入触发该 agent 的指令（如 ~start / ~design / ~music / ~prompt）。
```

### 制片人发现未处理反馈时（进阶段前）

```
🔄 **检测到上一轮的待处理反馈**：

来自 {下游 agent 名}：
- 问题：{问题摘要}
- 影响：{影响摘要}
- 建议修复：{修复方向}

我将在进入下一阶段前，先 Resume {对应上游 agent} 处理这条反馈。处理完会更新对应文档并标记反馈为已处理。
```

## 错误 / 兜底提示

### 缺少前置文件

```
⚠️ 请先完成{前置阶段名}！

输入 **{对应指令}** 开始。
```

### 跳过音乐确认

```
本集将跳过音乐设计（适合 ASMR / 纯环境音 / 已有完整音乐方案的项目）。

确认跳过？（输入 **是** 确认 / 任意其他内容取消）
```

### `~settings` 编辑

```
当前剧本设定：

{展示 assets/story/script-settings.md 内容}

你想修改哪一项？
1. 视觉风格
2. 目标媒介 + 目标平台
3. 目标受众画像
4. 对标爆款
5. 色彩锚（等同 ~color）
6. 全部重做

输入编号，或直接告诉我你想改什么。
```

```
✅ 设定已更新。

下次跑任何阶段，agent 都会用新设定。如想立即生效已有产出，需手动重跑对应阶段。
```
