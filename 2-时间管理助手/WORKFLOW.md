## 📋 当前需求清单

### 需求1：Bug 修复流程
**触发时机**：发现 Bug 或用户报告问题  
**执行步骤**：
1. 同步更新版本号（三处：`service-worker.js` + `app.js` + `时间管理助手.html`）
2. 修复代码
3. 更新 `BUG_FIX_LOG.md`（顶部添加新版本记录）
4. 执行验证清单（7 项全部通过）
5. 提交到 Git（仅相关文件，中文简洁描述）
6. 通知用户测试

**验收标准**：
- [ ] 版本号三处同步
- [ ] BUG_FIX_LOG.md 已更新
- [ ] 验证清单全部通过
- [ ] Git 提交消息清晰

详细流程见 `CLAUDE.md` 中的「Bug 修复工作流」章节。

### 需求2：复盘中心开发（⚠️ 红线约束）

**触发时机**：开发或修改复盘中心相关功能  

**执行步骤**：
1. **强制检查红线清单**（必须全部符合）：
   - [ ] 修改是否只涉及 `review-center.html` / `review-engine.js` / `review-ui.js`？
   - [ ] 是否保证不修改 `app.js` / `app-core.js`？
   - [ ] 是否保证不写入 `tm_YYYY_wNN_*` 系列 LocalStorage key？
   - [ ] 是否保证 Service Worker 不缓存复盘中心文件？
   - [ ] 手机端是否看不到复盘中心入口？
2. 实施修改
3. **桌面端测试**：复盘中心功能正常
4. **手机端测试**（强制执行）：
   - [ ] 填表正常
   - [ ] 保存正常
   - [ ] 同步正常
   - [ ] 离线启动正常
   - [ ] 无新增报错
5. 如果手机端任何一项异常 → **立即回退代码**

**验收标准**：
- [ ] 红线清单全部通过
- [ ] 桌面端功能正常
- [ ] 手机端主应用功能完全不受影响

**复盘中心红线（不可违反）**：
1. **平台隔离**：复盘中心仅桌面端可用，严禁影响手机端
2. **架构独立**：复盘中心是独立应用，完全不修改主应用代码
3. **只读数据**：复盘中心只读 LocalStorage，不写入 `tm_YYYY_wNN_*` 系列 key
4. **SW 隔离**：复盘中心文件不走 Service Worker，不缓存，不离线

详细红线规则见 `CLAUDE.md` 中的「复盘中心开发红线」章节。

### 需求4：复盘中心 AI 提示词优化（⚠️ 持续迭代）

**触发时机**：
- 用户测试 AI 对话后提出改进意见
- 发现 AI 提问方式不符合用户习惯
- AI 对话质量不达预期

**核心理念**：
提示词优化是**持续迭代的过程**，不是一次性工作。需要通过真实对话反馈，不断调整提问方式、语言风格、切入角度，让 AI 更懂用户的表达习惯和思维方式。这也是 Claude 了解用户的过程。

**执行步骤**：
1. **记录问题**：
   - 用户反馈的具体问题（截图/文字）
   - AI 的具体表现（哪句话有问题）
   - 用户期望的表现（应该怎么说）

2. **分析原因**：
   - 提示词哪里导致了这个问题？
   - 是数据上下文问题还是 system prompt 问题？
   - 是禁止规则不够明确还是示例不够清晰？

3. **调整提示词**：
   - 修改 `src/review-engine.js` 中的相关函数
   - 优先修改：
     - `formatContextForPrompt` — 数据上下文
     - `buildChatSystemPrompt` — 对话提示词
     - 开场示例、禁止规则、正确示例

4. **记录到迭代日志**：
   - 更新 `AI_PROMPT_ITERATION_LOG.md`
   - 记录：版本号、优化目标、问题描述、修改内容、测试结果、待验证问题

5. **测试验证**：
   - 用户关闭并重新打开复盘中心
   - 加载相同周期数据
   - 开始对话，观察 AI 的第一句话和后续对话
   - 记录改进效果和新问题

6. **更新状态文件**：
   - 更新 `PROJECT_STATUS.md` 中的"复盘中心完成度"
   - 如有重大突破，更新"已完成的里程碑"

**验收标准**：
- [ ] 问题已记录到 `AI_PROMPT_ITERATION_LOG.md`
- [ ] 提示词已修改
- [ ] 用户测试后确认改进效果
- [ ] 新问题已记录到"待验证问题"

**禁止行为**：
- ❌ 一次性大改提示词（小步快跑，逐个优化）
- ❌ 不记录就修改（必须先记录问题和预期效果）
- ❌ 不测试就说"已优化"（必须用户实际测试确认）
- ❌ 忘记更新迭代日志（每次修改都要记录）

**重要提醒**：
- 这是一个**长期工作**，不是一次性任务
- 每次对话都是学习用户的机会
- 关注用户的用词、语气、思维方式
- 逐步让 AI 的风格贴近用户的表达习惯

详细迭代记录见 `AI_PROMPT_ITERATION_LOG.md`。

## 🎬 Claude 工作指引

### 每次启动时的标准流程
1. **读取文件**（2分钟）：
   - `PROJECT_STATUS.md` → 了解当前进度、焦点、待办
   - `WORKFLOW.md`（本文件）→ 了解当前工作流版本、标准流程
   - `CLAUDE.md` → 了解项目原则、红线、验证流程
2. **主动汇报**（不等用户发话）：
   - 当前主线任务
   - 关键指标
   - 下一步行动（P0/P1/P2）
3. **等待用户指令**

### 执行任务时的原则
1. **信息溯源**：不编造数据，所有信息必须有来源
2. **遵循标准流程**：WORKFLOW 中定义的流程必须严格执行
3. **实时更新状态**：任务完成后立即更新 `PROJECT_STATUS.md`
4. **红线不可碰**：复盘中心开发必须遵守红线，手机端测试强制执行

### 会话结束时的操作
1. 更新 `PROJECT_STATUS.md`（最后更新时间、当前焦点、待办事项、更新日志）
2. 检查是否需要更新 `WORKFLOW.md`
3. 主动告知用户"已更新状态，下次启动时自动读取"
