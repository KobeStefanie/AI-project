# 删除文件必须使用回收站

## 触发事件

2026-07-04，在整合职业规划文档时，我直接使用 `rm` 命令删除了6个文件，其中包括用户特别喜欢的"职业规划访谈报告-2026-07-03.md"。

由于该文件从未提交到git，导致**永久丢失，无法恢复**。

## 为什么这是个严重错误

1. **用户数据无价**：用户特别喜欢那份访谈报告，用于探索自己
2. **直接删除=永久丢失**：没有git历史、没有回收站、没有任何备份
3. **破坏信任**：用户明确表示很喜欢那份文档，结果被我删除了

## 正确做法（强制规则）

### ⚠️ 禁止使用 `rm` 命令

```bash
# ❌ 绝对禁止
rm file.md
rm -rf directory/

# ❌ 即使用户说"删除"也不能直接 rm
```

### ✅ 必须移动到回收站

**Windows系统**：
```bash
# 方案1：使用PowerShell
powershell -Command "Remove-Item '文件路径' -Recurse"

# 方案2：提醒用户手动删除
echo "请手动将以下文件移到回收站："
echo "- 文件1"
echo "- 文件2"
```

**或者提醒用户确认**：
```
我需要删除以下文件：
- 文件1.md
- 文件2.md

这些文件会永久删除且无法恢复。请确认：
1. 是否确定要删除？
2. 是否已有备份？
3. 是否需要我先移动到回收站？
```

## 例外情况

**唯一可以直接删除的情况**：
- 临时文件（明确标注为temp/tmp）
- 构建产物（node_modules、dist、build等）
- 用户明确说"永久删除"且已确认

**其他所有情况都必须使用回收站**

## 为什么回收站重要

1. **可恢复**：用户可以从回收站找回文件
2. **时间窗口**：给用户反悔的机会
3. **安全第一**：宁可麻烦一点，也不能丢失数据

## How to apply

每次需要删除文件时：
1. ❌ 不要直接 `rm`
2. ✅ 使用PowerShell移到回收站
3. ✅ 或提醒用户手动删除
4. ✅ 或询问用户是否确认删除

**这是铁律，没有例外（除非是临时文件）**
