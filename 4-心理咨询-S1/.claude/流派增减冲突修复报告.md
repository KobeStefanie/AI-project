# 流派增减与内容保存冲突修复报告

**修复时间**：2026-06-29  
**问题级别**：严重 🔴  
**状态**：已修复 ✅

---

## 问题描述

用户担心：**流派配置增减会与上传/编辑的内容产生冲突，导致核心功能被阉割**

### 原始问题

1. **临时存储**：编辑/上传的流派分析内容保存在浏览器 `localStorage`
2. **硬编码流派列表**：页面加载时从localStorage恢复内容，但流派列表硬编码为 `['大观派', 'CBT', '精神动力学', '人本主义', '存在主义']`
3. **冲突场景**：
   - 用户上传Word到"CBT流派分析"
   - 内容保存在localStorage
   - 用户在配置页面新增"叙事疗法"流派
   - 触发自动重新生成，所有HTML文件被覆盖
   - 虽然localStorage中还有数据，但硬编码的流派列表无法恢复新流派的内容

### 核心风险

❌ localStorage不是持久化方案  
❌ 换浏览器/清缓存会丢失数据  
❌ 流派增减导致内容丢失  
❌ 无法备份和版本控制  

---

## 解决方案

### 架构改造：从客户端存储 → 服务器端持久化

#### 1. 新增保存服务器（端口8766）

**文件**：`src/approach_analysis_server.py`

**功能**：
- 接收前端编辑/上传的内容
- 保存到 `data/visitors/{visitor_id}/visits/{visit_id}.json`
- 数据结构：
  ```json
  {
    "case_data": {
      "approach_analyses_html": {
        "大观派": "<html>...",
        "CBT": "<html>...",
        "叙事疗法": "<html>..."
      },
      "counselor_review_html": "<html>..."
    }
  }
  ```

**API接口**：
- `POST /save_approach` - 保存流派分析
- `POST /save_review` - 保存咨询师复盘

#### 2. 修改前端保存逻辑

**文件**：`src/generate_visit_details.py`

**变更**：
- `saveEdit()` 函数：localStorage → API调用
- `saveReviewEdit()` 函数：localStorage → API调用  
- Word上传后：自动调用 `/save_approach` API

**代码示例**：
```javascript
function saveEdit(approachName, visitorId, visitId) {
    const contentDiv = document.getElementById('analysis-content-' + approachName);
    const data = {
        approach: approachName,
        visitor_id: visitorId,
        visit_id: visitId,
        content: contentDiv.innerHTML
    };

    // 保存到服务器（不再是localStorage）
    fetch('http://localhost:8766/save_approach', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data)
    })
    .then(response => response.json())
    .then(result => {
        if (result.success) {
            alert('保存成功！内容已保存到服务器。');
            toggleEdit(approachName);
        }
    });
}
```

#### 3. 修改HTML生成逻辑

**文件**：`src/generate_visit_details.py`（函数 `generate_visit_detail_page`）

**变更**：优先读取已保存的HTML内容

**代码逻辑**：
```python
for approach_name in all_approaches:
    analysis_content = ''
    
    # 1. 优先读取已保存的HTML（编辑/上传后的内容）
    saved_html = visit_data.get('case_data', {}) \
                           .get('approach_analyses_html', {}) \
                           .get(approach_name, '')
    
    if saved_html:
        # 直接使用保存的HTML
        analysis_content = saved_html
    else:
        # 2. 如果没有，从processed案例读取默认数据并生成HTML
        case_file = CASES_PROCESSED / f"{case_id}.json"
        if case_file.exists():
            # 读取并生成默认HTML...
            analysis_content = generate_default_html(approach_data)
```

#### 4. 删除localStorage恢复代码

**删除的代码**（第515-546行）：
```javascript
// 页面加载时恢复已保存的编辑内容
window.addEventListener('DOMContentLoaded', function() {
    // 恢复流派分析
    ['大观派', 'CBT', '精神动力学', '人本主义', '存在主义'].forEach(approach => {
        const saved = localStorage.getItem(storageKey);
        if (saved) {
            contentDiv.innerHTML = data.content;
        }
    });
});
```

**原因**：不再需要从localStorage恢复，数据已在生成HTML时直接注入

## 修复后的流程

### 编辑保存流程
```
用户编辑 → 点击保存 
→ POST /save_approach (8766) 
→ 保存到 visit_id.json 的 approach_analyses_html 字段
→ 提示"保存成功"
```

### 重新生成流程
```
流派配置变更 
→ 触发自动重新生成 
→ generate_visit_details.py 读取 visit_id.json
→ 优先读取 approach_analyses_html（用户编辑的内容）
→ 如果没有，读取 processed 案例的默认数据
→ 生成新的HTML文件
→ 用户编辑的内容完好无损 ✅
```

### 数据流向对比

**旧架构（有问题）**：
```
编辑 → localStorage → 页面刷新时JS恢复
                    ↓
                  重新生成HTML覆盖
                    ↓
                  localStorage数据存在，但页面是新的
                    ↓
                  JS恢复时硬编码流派列表，新流派无法恢复 ❌
```

**新架构（已修复）**：
```
编辑 → API (8766) → visit_id.json (approach_analyses_html)
                          ↓
                    重新生成HTML
                          ↓
                    读取 approach_analyses_html
                          ↓
                    直接注入到HTML中 ✅
```
