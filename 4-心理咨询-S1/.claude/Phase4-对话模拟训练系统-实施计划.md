# Phase 4 — 对话模拟训练系统 实施计划

**创建时间**：2026-09-04  
**用户需求**：四项功能都需具备：AI扮演来访者、我扮演咨询师、AI实时督导、录音回放与复盘

---

## 一、系统概述

### 核心理念
基于真实接访案例，AI生成来访者人设并与用户进行实时对话模拟，训练不同流派技术运用。

### 四大核心功能

| 功能 | 说明 | 技术实现 |
|------|------|---------|
| **AI扮演来访者** | 基于真实档案生成一致的人设，模拟真实对话 | Claude API + 人设Prompt |
| **我扮演咨询师** | 用户实时输入咨询回应，AI实时理解并回应 | 对话界面 + 输入框 |
| **AI实时督导** | 对话过程中AI评估技术运用质量 | 实时分析 + 浮窗提示 |
| **录音回放与复盘** | 对话结束后生成完整报告 | 对话历史存储 + AI生成报告 |

```

      ↓
[对话界面启动] → 用户输入咨询回应
      ↓

#### Prompt 1: 生成来访者人设

```
你是一位专业的心理咨询案例模拟专家。请根据以下真实接访记录，生成一个一致的来访者人设，用于对话模拟训练。

{visit_data.dialogue}

【咨询师复盘】
{visit_data.counselor_review}

【来访者基本信息】
{visitor_profile}

---

请输出：
1. 来访者核心问题（3-5个关键点）
2. 情绪状态描述（用3-5个词概括）
3. 典型语言模式（来访者会说的话/不会说的话）
4. 防御机制（如有）
5. 对咨询师的期待（显性/隐性）

【要求】

```

#### Prompt 2: AI扮演来访者（对话中）

```
你正在扮演一位来访者，参与心理咨询对话模拟训练。

【来访者人设】
{persona}

【对话历史】
{dialogue_history}

【咨询师刚才说】
{user_last_input}

---

请以来访者身份自然回应，注意：
1. 保持人设一致性（情绪、语言风格、防御机制）
2. 根据咨询师的回应调整情绪（好的共情会让来访者更开放）
3. 不要刻意配合，模拟真实来访者的自然反应
4. 每次回应50-150字，避免过长
5. 用口语化、生活化的表达，避免专业术语

## 五、技术细节

### 5.1 实时督导的实现方式

**方案A（推荐）**：异步评估 + 延迟显示

```
用户输入 → AI来访者立即回应（优先级高）
             ↓
      后台异步调用督导API（2-3秒）
             ↓
      督导反馈以"浮窗"形式出现
```

**优势**：
- 对话流畅性不受影响
- 督导反馈有思考时间，更准确
- 用户可选择是否查看（不打断对话）

**方案B（备选）**：对话结束后统一评估

```
对话进行中：AI只扮演来访者，不督导
对话结束后：AI一次性评估所有咨询回应
```

**推荐方案A**，因为"实时督导"是用户明确需求。

---

### 5.2 录音回放的实现方式

**方案**：逐条按时间戳显示（非真实录音）

```html
<div id="replay-container">
  <!-- 初始状态：空 -->
</div>

<script>
let currentIndex = 0;
const dialogue = [...]; // 从session JSON读取

function replayNext() {
  if (currentIndex >= dialogue.length) return;
  const turn = dialogue[currentIndex];
  
  // 渲染一条对话
  const div = document.createElement('div');
  div.className = turn.role === 'counselor' ? 'msg-counselor' : 'msg-client';
  div.textContent = turn.content;
  document.getElementById('replay-container').appendChild(div);
  
  // 如果有督导反馈，显示浮窗
  if (turn.supervision_feedback) {
    showSupervisionPopup(turn.supervision_feedback);
  }
  
  currentIndex++;
  setTimeout(replayNext, 2000); // 每2秒播放下一条
}
</script>
```

**注**：不是真实语音录音，而是"对话重现"。如果未来需要真实录音，可集成Web Audio API。

### 5.3 AI督导的提示时机

**原则**：不打断对话，但要及时反馈

**实现**：
- 来访者回应完毕后，延迟1-2秒显示督导提示
- 督导提示以"浮窗"形式出现在右侧，不遮挡对话区
- 用户可点击"查看详情"展开完整反馈
- 用户可点击"隐藏督导"关闭浮窗（专注对话）

**示例督导提示样式**：

## 六、风险与应对

### 风险1：AI来访者不够真实

**应对**：
- 基于真实逐字稿生成人设，不编造
- Prompt中强调"不刻意配合"、"模拟真实抗拒"
- 测试时用多个案例验证一致性

### 风险2：实时督导延迟影响体验

**应对**：
- 采用异步评估 + 浮窗显示
- 督导提示简短（30字以内）
- 用户可选择隐藏督导专注对话

### 风险3：用户"作弊"（看着真实逐字稿模拟）

**应对**：
- 训练界面不显示真实逐字稿
- 只显示来访者人设和核心问题
- 报告中强调"模拟训练"，不是复刻真实咨询

### 风险4：不同流派督导标准不一致

**应对**：
- 每个流派使用独立的督导Prompt
- Prompt中明确该流派的核心技术清单
- 评分标准基于该流派的理论框架
