## 🎯 3步上手

### 第1步：写问题 (1分钟)

```bash
cat > /tmp/my_question.json << 'EOF'
{
  "model": "gpt-5.5",
  "messages": [
    {
      "role": "system",
      "content": "你是Codex代码审查员"
    },
    {
      "role": "user",
      "content": "审查这段代码的SQL注入风险：\n\n[粘贴代码，不要超过500行]"
    }
  ],
  "temperature": 0.3,
  "max_tokens": 3000
}
EOF
```

**⚠️ 注意**：
- 代码不要超过500行（避免JSON过大）
- 复杂代码建议分批审查

## 🐛 常见问题

### Q1: 为什么返回"Failed to parse request body"？

**原因**：JSON中嵌入的代码太长或包含特殊字符

**解决**：
1. 代码不超过500行
2. 避免嵌入完整Vue/React组件（太长）
3. 用``\`\`\```包裹代码块

---

### Q2: 可以同时运行多个任务吗？

**答**：可以，但`codex-poll-auto.sh`只检查最新任务。

如果需要并发，手动指定job_id：
```bash
bash .harness/codex-poll.sh
```

---

### Q3: 如何取消任务？

```bash
rm .harness/codex-jobs/latest.json
```

---

### Q4: 超时时间可以改吗？

**可以**：
```bash
# 改成10分钟
export CODEX_TIMEOUT_SECONDS=600
bash .harness/codex-poll-auto.sh
```

## 🎯 最佳实践

### ✅ DO（推荐）

1. **问题要具体**
   - ❌ "这段代码有问题吗？"
   - ✅ "检查SQL注入、空指针、事务管理"

2. **给足够上下文**
   - ✅ 包含类名、方法名、背景说明
   - ✅ 说明这是什么项目、用什么框架

3. **代码要精简**
   - ✅ 只给相关代码（300-500行）
   - ❌ 粘贴整个文件（2000行）

---

### ❌ DON'T（避免）

1. **不要嵌入超长代码**
   - 超过500行会导致JSON解析失败

2. **不要问太宽泛的问题**
   - "审查整个项目" ← 太宽泛
   - "审查用户登录模块" ← 合适

3. **不要在JSON中用单引号**
   - JSON只支持双引号 `"`

## 🔧 故障排查

### 问题1：任务一直running

**检查**：
```bash
cat .harness/codex-jobs/latest.json
cat .harness/codex-jobs/*/status.json
```

**可能原因**：
- Codex API响应慢（正常，等待即可）
- 网络问题（检查网络）
- API密钥过期（联系管理员）

---

### 问题2：返回错误信息

**查看错误日志**：
```bash
cat .harness/codex-jobs/*/error.log
```

**常见错误**：
- `Failed to parse request body` → JSON格式问题
- `401 Unauthorized` → API密钥过期
- `429 Too Many Requests` → 请求过于频繁
