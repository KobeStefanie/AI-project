## 一、项目概况

### 1.1 核心架构

**来访者为中心架构** ([来访者为中心架构说明.md](D:\AI-项目\4-心理咨询-S1\docs\来访者为中心架构说明.md))

```
来访者档案 (Visitor Profile)
  ├─ 基本信息
  ├─ 家庭结构
  └─ 来访记录 (Visit Records)
       ├─ Visit 1
       │   ├─ 咨询师复盘 (Counselor Review)
       │   ├─ 录音文件 (Recordings)
       │   ├─ 逐字稿 (Transcript)
       │   └─ 流派分析 (Approach Analyses)
       │       ├─ 大观学派（危机干预）
       │       ├─ 认知行为疗法 (CBT)
       │       ├─ 精神动力学
       │       └─ ...
       ├─ Visit 2
       └─ Visit N
```

**设计原则**：
- 以来访者为中心，不是以案例为中心
- 每次来访记录独立存储
- 支持多流派分析
- 支持流派动态配置

### 1.2 技术栈

**后端**：
- Python 3.12
- Flask (多个微服务)
- 本地JSON文件存储

**前端**：
- 纯HTML + JavaScript
- Tailwind CSS
- Font Awesome图标

**服务器列表** ([服务器列表.md](D:\AI-项目\4-心理咨询-S1\.claude\服务器列表.md))：
- 端口8003: 配置服务器 (config_server.py)

## 二、昨天到今天解决的问题

### 2.1 流派增减冲突问题 ✅

**问题**：流派配置变更会导致已编辑的内容丢失

**原因**：使用localStorage存储，流派配置变更后数据不同步

**解决方案**：
1. 改为服务器端JSON持久化存储
2. 创建保存服务器 (approach_analysis_server.py)
3. 自动触发HTML重新生成

**文档**：[流派增减冲突修复报告.md](D:\AI-项目\4-心理咨询-S1\.claude\流派增减冲突修复报告.md)

### 2.2 Word上传后刷新丢失问题 ✅

**问题**：Word上传后，刷新页面内容就消失

**原因**：数据保存到JSON了，但HTML文件没有重新生成

**解决方案**：
1. 保存API自动触发HTML重新生成
2. 使用subprocess.Popen异步执行

**文档**：[Word上传刷新丢失修复.md](D:\AI-项目\4-心理咨询-S1\.claude\Word上传刷新丢失修复.md)

### 2.3 流派名称不匹配问题 ✅

**问题**：流派配置变更后，所有保存、上传、编辑功能失效

**根本原因**：硬编码的流派列表与配置文件不同步

**核心问题**：
```python
# generate_visit_details.py 硬编码
all_approaches = ['大观派', 'CBT', '精神动力学', ...]

# 配置文件中的实际名称
"name": "大观学派（危机干预）"  # 不是"大观派"
"name": "认知行为疗法 (CBT)"    # 不是"CBT"
```

**解决方案**：
1. 改为动态加载流派配置
2. 数据迁移：旧名称 → 新名称
3. 使用流派ID映射

**文档**：[流派名称不匹配修复.md](D:\AI-项目\4-心理咨询-S1\.claude\流派名称不匹配修复.md)

### 2.4 流派配置自动重新生成问题 ✅

**问题**：流派配置变更后，需要手动重新生成HTML

**根本原因**：config_server.py 调用了不存在的脚本

```python
# 错误的脚本名称
detail_script = os.path.join(PROJECT_ROOT, 'src', 'generate_visit_details_v2.py')
# 这个文件不存在！
```

**解决方案**：
1. 修复脚本路径为 `generate_visit_details.py`
2. 流派配置保存时自动触发HTML重新生成

**文档**：[流派配置自动重新生成修复.md](D:\AI-项目\4-心理咨询-S1\.claude\流派配置自动重新生成修复.md)

### 2.5 流派删除保留内容规则 ✅

**需求**：删除流派时，原有的内容不删除

**实现**：
1. JSON中的数据永久保留
2. 已删除的流派自动显示为"已归档"
3. 视觉标识：半透明 + 斜体 + "(已归档)"标签
4. 重新添加同名流派，内容自动恢复

**文档**：[流派删除保留内容规则.md](D:\AI-项目\4-心理咨询-S1\.claude\流派删除保留内容规则.md)

### 3.3 核心工作流程

#### 流派配置变更流程

```
用户修改配置
    ↓
POST http://localhost:8003/api/approaches
    ↓
config_server.py 保存配置文件
    ↓
自动调用 generate_visit_details.py
    ↓
动态加载最新流派配置
    ↓
重新生成所有HTML文件
    ↓
返回成功消息
```

#### 内容保存流程

```
用户编辑内容
    ↓
点击"保存"
    ↓
POST http://localhost:8766/save_approach
    ↓
approach_analysis_server.py 保存到JSON
    ↓
自动调用 generate_visit_details.py
    ↓
重新生成HTML
    ↓
返回成功消息
```

#### Word上传流程

```
用户选择Word文件
    ↓
POST http://localhost:8765/
    ↓
word_upload_server.py 解析Word
    ↓
返回HTML内容
    ↓
前端自动调用保存API
    ↓
POST http://localhost:8766/save_approach
    ↓
保存并重新生成HTML
```

## 九、关键决策记录

### 9.1 为什么选择JSON文件而不是数据库？

**决策**：使用本地JSON文件存储

**理由**：
- 单用户场景，不需要复杂的并发控制
- 数据可读性强，便于调试和备份
- 迁移和部署简单
- 符合"来访者为中心"的文件组织方式

**权衡**：
- 性能：小规模数据足够
- 扩展性：将来可以迁移到数据库

### 9.2 为什么使用多个服务器而不是单一服务器？

**决策**：每个功能独立服务器

**理由**：
- 职责单一，易于维护
- 独立重启，不影响其他功能
- 便于调试和日志查看

**权衡**：
- 需要管理多个进程
- 端口管理稍复杂

### 9.3 为什么流派配置变更要自动重新生成HTML？

**决策**：config_server.py自动触发重新生成

**理由**：
- 保证配置和页面同步
- 用户无需手动操作
- 避免功能失效

**权衡**：
- 性能开销（可以优化为增量生成）
- 保存时间稍长
