## 一、功能概述

### 1.1 核心设计理念

每个流派分析背后都会跟一条"感悟"，这个感悟会持续更新迭代。

- **流派视角标注**: 每条感悟都与特定流派关联（如"大观学派（危机干预）"、"认知行为疗法 (CBT)"）
- **持续迭代**: 支持添加、编辑、删除，记录对同一案例在不同时间的理解变化
- **时间追踪**: 记录创建时间和最后修改时间

## 二、实施内容

### 2.1 后端API（approach_analysis_server.py）

**端口**: 8766

新增3个API端点：

#### ✅ POST `/supervision_record/add`
添加感悟记录

**请求参数**:
```json
{
  "visitor_id": "V20260616001",
  "visit_id": "visit_001",
  "approach": "大观学派（危机干预）",
  "content": "从大观学派视角看，这个案例..."
}
```

**响应**:
```json
{
  "success": true,
  "message": "感悟添加成功",
  "record_id": "sr_001"
}
```

**功能**:
- 自动生成唯一ID（sr_001, sr_002...）
- 记录创建时间和更新时间
- 自动触发HTML重新生成

#### ✅ POST `/supervision_record/edit`
编辑感悟记录

**请求参数**:
```json
{
  "visitor_id": "V20260616001",
  "visit_id": "visit_001",
  "record_id": "sr_001",
  "approach": "大观学派（危机干预）",
  "content": "重新理解后，我认为..."
}
```

**响应**:
```json
{
  "success": true,
  "message": "感悟编辑成功"
}
```

**功能**:
- 更新内容和流派
- 更新最后修改时间
- 保留原始创建时间

#### ✅ POST `/supervision_record/delete`
删除感悟记录

**请求参数**:
```json
{
  "visitor_id": "V20260616001",
  "visit_id": "visit_001",
  "record_id": "sr_001"
}
```

**响应**:
```json
{
  "success": true,
  "message": "感悟删除成功"
}
```

### 2.3 数据结构

#### visit JSON中的存储

**位置**: `data/visitors/{visitor_id}/visits/{visit_id}.json`

```json
{
  "visit_id": "visit_001",
  "visitor_id": "V20260616001",
  "case_data": {
    "case_id": "C20260616001",
    "supervision_records": [
      {
        "id": "sr_001",
        "approach": "大观学派（危机干预）",
        "content": "从大观学派视角看，这个案例的核心是...",
        "created_at": "2026-06-29T12:30:00",
        "updated_at": "2026-06-29T12:30:00"
      },
      {
        "id": "sr_002",
        "approach": "认知行为疗法 (CBT)",
        "content": "从CBT角度分析，来访者的自动思维...",
        "created_at": "2026-06-29T14:00:00",
        "updated_at": "2026-06-29T15:20:00"
      }
    ]
  }
}
```

**字段说明**:
- `id`: 唯一标识符，格式 `sr_XXX`（自动生成）
- `approach`: 流派名称（与流派配置中的name一致）
- `content`: 感悟内容（支持换行）
- `created_at`: 创建时间（ISO 8601格式，永不改变）
- `updated_at`: 最后修改时间（每次编辑更新）

## 三、使用流程

### 3.1 添加感悟

**步骤**:
1. 打开来访详情页（如 `V20260616001/visit_001.html`）
2. 切换到目标流派标签页（如"大观学派"）
3. 滚动到页面底部，找到"历次感悟"区域
4. 点击"添加感悟"按钮
5. 在弹出的对话框中输入感悟内容
6. 点击"添加"按钮
7. 看到成功提示后，页面自动刷新
8. 新的感悟显示在列表顶部

**注意**:
- 流派视角自动设置为当前标签页的流派
- 感悟内容为必填项
- 支持多行输入

### 3.2 编辑感悟

**步骤**:
1. 在感悟卡片上点击"编辑"按钮
2. 修改感悟内容
3. 点击"保存修改"
4. 页面自动刷新显示更新后的内容

**变化**:
- 内容更新
- `updated_at` 时间更新
- 显示"(已编辑)"标记

### 3.3 删除感悟

**步骤**:
1. 在感悟卡片上点击"删除"按钮
2. 确认删除
3. 页面自动刷新，感悟已移除

## 四、技术特点

### 4.1 流派关联设计

✅ **每个流派独立的感悟列表**
- 在"大观学派"标签页只显示大观学派视角的感悟
- 在"CBT"标签页只显示CBT视角的感悟
- 不同流派的感悟互不干扰

✅ **流派视角自动标注**
- 点击"添加感悟"时，自动设置为当前流派
- 流派字段在对话框中显示为只读
- 避免用户手动选择出错

### 4.2 时间追踪

✅ **双时间戳设计**
- `created_at`: 首次创建时间，永不改变
- `updated_at`: 最后修改时间，每次编辑更新

✅ **编辑标记**
- 如果 `created_at != updated_at`，显示"(已编辑)"
- 用户可以知道哪些感悟经过了修改

### 4.3 自动重新生成HTML

✅ **后端自动触发**
- 添加/编辑/删除感悟后，自动调用 `generate_visit_details.py`
- 使用 `subprocess.Popen` 异步执行，不阻塞响应
- 用户刷新页面即可看到更新

✅ **Windows兼容**
- 使用 `CREATE_NO_WINDOW` 标志，不弹出黑窗口
- 重定向输出到 `DEVNULL`，避免干扰

### 4.4 数据安全

✅ **内容转义**
- JavaScript中对感悟内容进行转义处理
- 防止单引号、双引号破坏HTML结构
- 支持换行符（`\n` → `<br>`）

✅ **时间戳更新**
- 每次修改都更新 `metadata.updated_at`
- 便于追踪数据变更历史

### 4.5 用户体验

✅ **即时反馈**
- 操作成功后显示提示消息
- 500ms延迟后自动刷新页面
- 用户无需手动刷新

✅ **确认对话框**
- 删除操作需要二次确认
- 防止误删重要内容

✅ **空状态提示**
- 无感悟时显示友好提示
- 引导用户点击"添加感悟"按钮

## 七、注意事项

### 7.1 服务器依赖

感悟功能依赖以下服务器：
- **approach_analysis_server.py (8766)**: 提供感悟管理API
- 其他服务器不影响此功能

### 7.2 并发安全

当前实现是简单的文件读写，不支持并发：
- 不要同时在多个浏览器窗口编辑同一来访记录
- 如需并发支持，需要引入锁机制

### 7.3 数据备份

虽然有自动HTML重新生成，但建议：
- 定期手动备份整个 `data/` 目录
- 重要修改前先备份
- visit JSON是唯一数据源
