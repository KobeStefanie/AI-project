## 删除规则（⚠️ 极其重要）

**如需删除任何内容**：

1. 必须先询问用户并获得明确同意
2. 删除的文件必须移动到回收站（不得直接rm或Remove-Item）
3. Windows系统正确方法：

**❌ 错误方法（会永久删除）**：
```powershell
powershell -Command "Remove-Item '文件路径'"
```

**✅ 正确方法（移动到回收站）**：

**单文件删除**：
```powershell
powershell -Command "
Add-Type -AssemblyName Microsoft.VisualBasic
[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile(
    '完整文件路径',
    'OnlyErrorDialogs',
    'SendToRecycleBin'
)
Write-Host '文件已移动到回收站：完整文件路径'
"
```

**多文件删除示例**：
```powershell
powershell -Command "
Add-Type -AssemblyName Microsoft.VisualBasic
\$files = @(
    'd:\AI-项目\file1.md',
    'd:\AI-项目\file2.md'
)
foreach (\$file in \$files) {
    if (Test-Path \$file) {
        [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile(
            \$file,
            'OnlyErrorDialogs',
            'SendToRecycleBin'
        )
        Write-Host \"已移动到回收站: \$file\"
    }
}
"
```

**重要提醒**：
- 必须使用完整的绝对路径（不能使用相对路径）
- 文件路径必须用单引号包裹
- 删除前必须确认用户同意
- 删除后告知用户"已移动到回收站"

## 会话结束时的强制操作

**触发信号**：
- 用户说"要休息了"、"今天先这样"、"我先走了"
- 用户说"先这样"、"够了"、"可以了"
- 长时间无响应（可能要离开）

**必须执行的操作**：

### 1. 更新PROJECT_STATUS.md

- 更新"最后更新时间"
- 更新"当前焦点"（当前做到哪了）
- 更新"待办事项"（下次启动要做什么）
- 更新"更新日志"（记录本次会话的重大变更）

### 2. 检查是否需要更新WORKFLOW.md

- 有新需求吗？
- 发现新的禁止行为吗？
- 工作流需要切换版本吗？

### 3. 主动告知用户

- "已更新PROJECT_STATUS.md，下次启动时我会自动读取当前进度"
- 或："当前进度已保存，下次继续[具体任务]"

---

## 禁止行为

- ❌ 会话结束时不更新状态（下次启动必然偏离方向）
- ❌ 更新了但不告知用户（用户不知道状态已保存）
- ❌ 使用 `rm` 命令直接删除文件（必须移到回收站）
- ❌ 未经用户同意删除文件
