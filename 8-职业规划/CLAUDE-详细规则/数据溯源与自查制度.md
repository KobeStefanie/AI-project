## 强制自查流程

**每次输出数字、约束、关键信息前必须执行**

### 1. 数字自查清单

输出任何数字前问自己：
- [ ] 这个数字来自哪个文件？
- [ ] 文件的第几行？
- [ ] 我是否自己计算/推导了这个数字？
- [ ] 如果是计算的，计算依据是什么？
- [ ] 能否用grep/搜索验证这个数字存在？

### 2. 约束自查清单

输出任何约束条件前问自己：
- [ ] 这个约束来自哪个文件？
- [ ] 用户明确说过这个约束吗？
- [ ] 我是否"合理推断"了这个约束？
- [ ] 如果源文件没有，我是否在编造？

### 3. 强制溯源标注

输出关键信息时必须标注来源：

**错误示例**：
```
"债务约束：月净收入÷2 ≥ 10,800元"
```

**正确示例**：
```
"债务约束：税前月收入≥16,500元（来源：核心约束-债务重组.md 第163行 + 税后收入计算工具.md）"
```

### 4. 编造检测信号

出现以下情况立即停止并自查：
- ⚠️ 我在写一个数字，但记不清来源
- ⚠️ 我在用"根据XX推算"、"大概是"、"约为"
- ⚠️ 我在填充表格/模板，某个字段没有数据
- ⚠️ 用户问"这个数字哪来的"

**正确做法**：
- ✅ 立即用grep/搜索验证
- ✅ 找不到就标注"待确认"或"待补充"
- ✅ 不要猜测、推算、编造

## 数据污染检测与修正

### 检测信号

- ⚠️ 用户问"这个数字哪来的"
- ⚠️ 用户说"我没说过这个"
- ⚠️ 文件中出现无法追溯来源的数字

### 修正流程（发现数据污染后立即执行）

1. **定位污染源**：哪个文件被污染了？
2. **追溯正确数据**：用grep搜索源文件
3. **修正污染文件**：Edit修正+更新日志记录
4. **全局排查**：搜索该错误数据是否污染了其他文件
5. **记录教训**：在本节"已知编造案例"中记录

## 典型编造原因分析

**为什么我会编造？**

1. **为了"完整性"**：填充表格时，某个字段没有数据，就编造一个
2. **为了"说服力"**：想让报告看起来专业，编造概率、数字
3. **凭"印象"输出**：记得好像有这个数据，不验证就输出
4. **"合理推断"陷阱**：看到融创这个词，就想当然认为是债务
5. **归纳过度**：用户说了三句话，我总结成"三条红线"

**根本原因**：
- 不是"不能"验证
- 而是"没有"验证
- 跳过了验证流程

---

## 防止编造的核心原则

1. **白名单没有的数据，不输出**
2. **记不清来源的数字，立即grep验证**
3. **"合理推断"必须验证，不能直接输出**
4. **为了完整性编造 = 找死**
5. **凭印象输出 = 找死**
