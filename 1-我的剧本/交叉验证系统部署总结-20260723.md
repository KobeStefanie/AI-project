## 核心机制分析

**原系统（软件开发部署）**：
- 第一步：Claude自检（编译、多租户、字段对齐、日志、权限、状态文档）
- 第二步：Codex审查（外部AI交叉验证）
- 第三步：对比结论（两个AI的结论对比，分歧时以更严格的为准）

**核心价值**：
- 防止单一视角盲点
- 交叉验证提升质量
- 黑断机制保障底线

## 适配到自我探索项目

### 映射关系

| 原系统 | 适配后 |
|--------|--------|
| 部署代码 | 深度探索会话结束 / 重大决策 / 阶段整合 |
| Claude自检 | 治疗师自检（文件、内容、状态） |
| Codex审查 | Workflow Agent交叉验证 |
| 对比结论 | 对比表格（分歧以更严格为准） |
| 生成报告 | 更新PROJECT_STATUS.md |
| 部署黑断 | 验证黑断（未通过禁止继续） |

### 三大应用场景

**场景1：深度探索会话结束验证**
- 自检6项：文件夹、对话记录、核心发现、总结、认知地图、项目状态
- 任一未通过 → 触发Workflow多视角验证
- 黑断：所有项必须✓，否则禁止进入下次会话

**场景2：重大决策交叉验证**
- 自检5项：Self占比≥60%、她的影响、沉没成本、管理者焦虑、流放者驱动
- Self＜60%或有她的影响 → 触发3个agent（职业/心理/认知）交叉评估
- 黑断：Self≥60%、无她的影响、至少2个视角支持

**场景3：阶段性整合质量检查**
- 自检5项：重复循环、认知天花板、Self占比趋势、探索逃避、工作流版本
- 有问题 → 触发全局复盘workflow（4维度pipeline评估）
- 黑断：无重复循环、Self趋势稳定、行动探索比例合理
