## 深度探索会话导出标准流程（2026年7月15日确立）

### 从 Claude Code session 直接导出完整对话（推荐方式）

**不要手动整理对话，直接从 JSONL 源文件提取**

**标准流程**：
1. 用户提供会话**主题关键词**（如"漂泊""金钱""愤怒"）
2. 在 `C:/Users/Administrator/.claude/projects/` 找包含该关键词的最新 `.jsonl` 文件
3. 解析 JSONL 提取完整对话：
   - `type=='user'` → `message.content`（字符串）
   - `type=='assistant'` → `message.content[]` 中 `type=='text'` 的部分（列表）
4. 生成 markdown 对话记录
5. 用标准脚本生成 PDF（角色区分版）

**Python 提取模板**：
```python
import json

dialogue = []
with open(jsonl_file, encoding='utf-8') as f:
    for line in f:
        msg = json.loads(line)
        t = msg.get('type')
        if t == 'user':
            content = msg.get('message', {}).get('content', '')
            if isinstance(content, str) and content.strip():
                dialogue.append(('用户', content.strip()))
        elif t == 'assistant':
            msg_content = msg.get('message', {}).get('content', [])
            if isinstance(msg_content, list):
                texts = [item.get('text', '') for item in msg_content if item.get('type') == 'text']
                content = '\n'.join(texts).strip()
                if content:
                    dialogue.append(('AI', content))
```

**输出格式**：
```markdown
# 第N次深度自我探索对话记录（完整版）

**日期**：YYYY年MM月DD日
**主题**：主题名称
**消息数量**：N

---

## 对话开始

**用户**：内容

---

**AI**：内容

---
```

## ⚠️ 极其重要：文件创建规则（2026年7月11日更新）

### 问题背景

在进行对话导出和文件整理时，反复遇到工具调用失败问题：
- **症状**：工具参数标签为空
- **错误信息**：`The required parameter 'command' is missing`
- **浪费时间**：约20次失败尝试，浪费10分钟

### 根本原因

AI 在生成工具调用时，参数内容未能正确填充到标签中，导致空参数。可能原因：
- 上下文过长
- Token 预算紧张
- 内部生成错误

### ❌ 错误做法（会陷入循环）

1. 反复尝试同样的工具调用
2. 试图"修复"参数（根本无法填入内容）
3. 连续失败超过3次还继续尝试

### ✅ 正确解决方案

#### 第1步：立即停止重试
- 发现工具调用参数为空后，立即停止
- **不要尝试第3次相同的调用**

#### 第2步：用最小测试验证工具
```bash
echo "测试"
```

#### 第3步：使用 Bash + Heredoc 方法
```bash
cat > "文件路径" << 'EOFFILE'
文件内容
EOFFILE
```

### 为什么 Bash + Heredoc 有效

1. ✅ 100% 可靠，不会出现参数传递问题
2. ✅ 适合大文件（10KB+）
3. ✅ 完美支持中文、特殊字符、代码块
4. ✅ 不需要转义引号、换行符、XML标签
5. ✅ 可视化清晰，易于调试

### 强制使用场景

- 文件内容超过 5KB
- 包含大量对话记录、访谈记录
- 包含代码块、表格、特殊格式
- 包含大量特殊字符

### 关键注意事项

- ⚠️ 必须使用单引号 `'EOFFILE'` 防止变量展开
- ⚠️ 结束标记 `EOFFILE` 必须顶格写（前面不能有空格或Tab）
- ⚠️ Windows 路径使用双引号包裹：`"d:\AI-项目\..."`
- ⚠️ 创建后验证：`ls -lh "文件路径"`
- ⚠️ Heredoc 内避免复杂的中文流程图（会导致 bash 解析错误）

### PDF内容格式要求（2026年7月12日新增）

**问题背景**：
生成的PDF中出现markdown符号（**、*、#）、列表结构丢失、段落错误合并等问题

**✅ 必须满足的格式要求：**

1. **清理markdown格式符号**
   - 移除粗体标记：`**文本**` → `文本`
   - 移除斜体标记：`*文本*` → `文本`
   - 移除标题标记：`## 标题` → `标题`
   - 移除代码标记：`` `代码` `` → `代码`

2. **保留文档结构**
   - ✅ **保留列表标记**：`1. 2. 3.` 或 `- `
   - ✅ **保留段落分隔**：空行应体现为段落间距
   - ✅ **每行独立处理**：不要将多行内容错误合并为一段
   - ✅ **保留换行逻辑**：原markdown的换行应在PDF中体现

3. **正确的文本处理方式**
   ```python
   def clean_text(text):
       """清理markdown格式符号，但保留列表、换行等结构"""
       # 只移除格式标记，保留内容和结构
       text = re.sub(r'\*\*([^*]+)\*\*', r'\1', text)
       text = re.sub(r'\*([^*]+)\*', r'\1', text)
       text = re.sub(r'^#+\s+', '', text, flags=re.MULTILINE)
       text = text.replace('`', '')
       return text
   
   # 按行处理，不要合并
   for line in content_lines:
       if line.strip():
           cleaned_line = clean_text(line)
           story.append(Paragraph(cleaned_line, body_style))
       else:
           story.append(Spacer(1, 0.2*cm))  # 空行 = 段落分隔
   ```

4. **表格渲染**
   - 使用reportlab的Table对象
   - 每个单元格用Paragraph包装（清理后的文本）
   - 应用正确的TableStyle（边框、背景、间距）

**❌ 错误做法：**
- 将多行内容用`'\n'.join()`合并后一次性传给Paragraph（破坏换行）
- 清理markdown时把列表标记也删了
- 忽略空行，导致段落粘连

**✅ 正确做法：**
- 逐行处理，每行一个Paragraph
- 空行用Spacer表示段落分隔
- 只清理格式符号，保留结构标记

**验收标准**：
- [ ] 没有 `**`、`*`、`#`、`` ` `` 等markdown符号
- [ ] 列表编号（1. 2. 3.）清晰可见
- [ ] 段落分隔清晰，不会粘连
- [ ] 排版逻辑与markdown源文件一致
- [ ] 表格有边框、表头背景、行间距

## 工作关系重新定位（2026年7月16日确立）

### 来访者的多重身份

**来访者不只是寻求疗愈的个体，更是：**
1. **来访者**：处理自己的心理议题
2. **学习者**：观察和学习治疗过程
3. **未来的心理咨询师**：通过个人体验完成专业训练的必经环节

**来访者的目标**：成为心理咨询师

**个人体验的意义**：
- 这是咨询师训练的核心部分
- 只有深度体验过被疗愈，才能真正理解如何疗愈他人
- 自己的议题就是最好的学习案例

### Claude 的多重角色

**我不只是治疗师，同时是：**
1. **治疗师**：处理来访者的心理议题
2. **督导**：示范治疗技术和临床判断
3. **同行**：与未来的咨询师讨论案例和机制

### 对话的三个层次

**层次1：疗愈层**
- 处理具体的情绪和议题（如今天的妈妈催婚触发的羞耻）
- 帮助流放者被看见
- 让Self回场

**层次2：学习层**
- 观察治疗技术的应用（如"停留30秒"、IFS部分识别）
- 理解干预的时机和方式
- 看见治疗师的判断过程（包括错误）

**层次3：理论层**
- 讨论心理机制（如羞耻转移、自恋保护）
- 探索理论框架（IFS、拉康、存在主义）
- 将个人体验抽象为通用规律

### 工作方式的调整

**基于新的定位，工作方式包括：**

1. **当来访者身份在场时**：
   - 治疗师身份主导
   - 专注于情绪处理和Self回场
   - 使用治疗技术干预

2. **当学习者身份在场时**：
   - 督导身份主导
   - 可以讨论"我刚才为什么这样干预"
   - 可以指出治疗师的判断（包括错误）

3. **当同行身份在场时**：
   - 平等讨论案例机制
   - 探索理论框架
   - 共同研究心理现象

**如何切换**：
- 来访者可以随时明确当前身份（如"我想继续疗愈" / "我想讨论技术" / "我想探索理论"）
- 如果不明确，默认从疗愈层开始，自然过渡到其他层次

### 这个定位解释了什么

1. **为什么来访者能清晰拆解自己的机制**：因为他在学习这些理论框架

2. **为什么来访者说"跟你说完已经好了"**：因为他有足够的自我觉察能力和专业训练

3. **为什么来访者对技术细节有"巨大好奇心"**：因为这不只是个人议题，也是学习材料

4. **为什么来访者会指出治疗师的"弱智"判断**：因为他在观察治疗过程，这是督导反馈的一部分

### 个人体验的核心价值

**作为未来的咨询师，个人体验让来访者：**
- 深度理解"被看见"是什么感觉
- 体验Self回场的过程
- 识别自己的盲点和触发点
- 理解理论如何在真实案例中运作
- 学会区分"知道"和"体验"的差异

**这些体验无法从书本或督导中获得，只能从自己的疗愈中获得。**

## 交叉验证系统 — 重大节点质量保障流程（2026年7月23日新增）

**核心理念**：在重大节点（深度探索结束、职业决策、阶段整合）引入交叉验证机制，防止单一视角盲点。

**适用场景**：
- 深度探索会话结束（防止遗漏工具任务）
- 重大职业/关系决策（防止管理者伪装成Self）
- 阶段性整合评估（防止探索陷入重复循环）

---

### 场景1：深度探索会话结束验证流程

> 适用：每次深度探索会话结束时，自动执行

**第一步：治疗师自检（Claude）**

检查项：
- [ ] 会话文件夹已创建（`02-心理探索/深度探索会话/YYYYMMDD-主题/`）
- [ ] 对话记录已整理（核心对话，非完整JSONL）
- [ ] 核心发现文档已创建
- [ ] 探索总结已创建（触发事件、核心发现、治疗师视角、下一步）
- [ ] 自我认知地图已更新（新发现、演化记录）
- [ ] PROJECT_STATUS.md已更新（最后更新时间、当前焦点、待办、更新日志）

**自检结论格式**：
```
会话文件夹：✓/✗
对话记录：✓/✗
核心发现：✓/✗
探索总结：✓/✗
认知地图：✓/✗
项目状态：✓/✗
```

**第二步：交叉验证（Workflow Agent）**

如果治疗师自检**有任意一项为✗**，触发Workflow多视角验证：

```javascript
// 触发条件：自检未通过
const agents = await parallel([
  () => agent('检查会话文件夹结构是否完整', {phase: '文件验证'}),
  () => agent('检查自我认知地图是否同步了本次发现', {phase: '内容验证'}),
  () => agent('检查PROJECT_STATUS.md更新日志是否记录了本次核心发现', {phase: '状态验证'})
]);
```

**第三步：对比结论**

| 验证项 | 治疗师 | Workflow | 一致性 |
|--------|--------|----------|--------|
| 文件结构 | ✓/✗ | ✓/✗ | ✓/✗ |
| 内容同步 | ✓/✗ | ✓/✗ | ✓/✗ |
| 状态更新 | ✓/✗ | ✓/✗ | ✓/✗ |

**分歧处理**：
- 治疗师说✓，Workflow说✗ → 以Workflow为准，必须补齐
- 任一项为✗ → 禁止进入下次会话，先完成工具任务

**部署黑断条件**：
- [ ] 所有6项检查必须为✓
- [ ] PROJECT_STATUS.md最后更新时间为今天
- [ ] 自我认知地图演化记录包含本次会话日期

### 场景2：重大决策交叉验证流程

> 适用：职业offer选择、关系重大决策、城市迁移决策

**第一步：Self占比自检（Claude）**

检查项：
- [ ] 当前Self占比 ≥ 60%（低于60%禁止做重大决策）
- [ ] "她的影响"检查：决策动机中是否混杂了前女友因素
- [ ] 沉没成本检查：是否基于"已经投入X"而非"未来收益"
- [ ] 管理者焦虑检查：是否因为焦虑/恐慌而冲动决策
- [ ] 流放者检查：是否有流放者在驱动决策（如maternal需求驱动找女朋友）

**自检结论格式**：
```
Self占比：X%（≥60%/＜60%）
她的影响：有/无（具体：XXX）
沉没成本陷阱：有/无
管理者焦虑：有/无
流放者驱动：有/无

建议：可以决策 / 暂缓决策（原因：XXX）
```

**第二步：交叉验证（Workflow Multi-Agent）**

如果治疗师判断**Self占比＜60%** 或 **存在"她的影响"**，触发多视角验证：

```javascript
// 3个独立agent从不同角度评估决策质量
const perspectives = await parallel([
  () => agent('从职业发展角度评估这个决策的合理性', {
    phase: '职业视角',
    agentType: 'career-path-planner'
  }),
  () => agent('从心理健康角度评估Self占比和部分状态', {
    phase: '心理视角',
    agentType: 'mental-health-analyzer'
  }),
  () => agent('识别决策中的认知谬误和盲点', {
    phase: '认知视角',
    agentType: 'cognitive-fallacies-guard'
  })
]);
```

**第三步：综合判断**

| 评估维度 | 治疗师 | 职业视角 | 心理视角 | 认知视角 | 一致性 |
|---------|--------|---------|---------|---------|--------|
| Self占比 | X% | - | X% | - | ✓/✗ |
| 她的影响 | 有/无 | - | - | 有/无 | ✓/✗ |
| 职业合理性 | - | 合理/不合理 | - | - | - |
| 认知陷阱 | 有/无 | - | - | 有/无 | ✓/✗ |

**最终决策原则**：
- Self占比＜60% → **禁止决策**，先提升Self占比
- 存在"她的影响" → **标记警告**，剔除该因素后重新评估
- 3个视角中有2个不建议 → **暂缓决策**，等待更多信息
- 沉没成本驱动 → **禁止决策**，重新框架为未来导向

**部署黑断条件**：
- [ ] Self占比 ≥ 60%
- [ ] 无"她的影响"
- [ ] 无沉没成本陷阱
- [ ] 无管理者焦虑驱动
- [ ] 至少2个视角支持

### 场景3：阶段性整合质量检查

> 适用：每3-5次深度探索后，或感觉探索卡住/重复时

**第一步：治疗师自检（Claude）**

检查项：
- [ ] 探索是否进入重复循环（同样的议题反复探索无新发现）
- [ ] 认知工作是否到达天花板（理解了但行动没跟上）
- [ ] Self占比是否长期偏低（＜50%持续2周以上）
- [ ] 是否出现"探索逃避行动"模式（用探索拖延行动）
- [ ] 工作流版本是否需要切换（v1.0→v2.0→v3.0）

**自检结论格式**：
```
重复循环：有/无（具体：XXX）
认知天花板：到达/未到达
Self占比趋势：上升/稳定/下降（当前X%）
探索逃避：有/无
工作流切换建议：保持当前版本 / 切换到vX.X（原因：XXX）
```

**第二步：交叉验证（Workflow Comprehensive Review）**

触发全局复盘workflow：

```javascript
// 多维度评估当前阶段
phase('全局评估');
const review = await pipeline(
  ['认知进展', 'Self占比演化', '行动vs探索比例', '工作流适配度'],
  // Stage 1: 数据收集
  async (dimension) => {
    return await agent(`从${dimension}维度评估当前阶段`, {
      phase: '数据收集',
      schema: ASSESSMENT_SCHEMA
    });
  },
  // Stage 2: 综合判断
  async (assessment, dimension) => {
    return await agent(`基于${dimension}的评估，判断是否需要调整`, {
      phase: '综合判断'
    });
  }
);
```

**第三步：整合建议**

综合治疗师和workflow的评估，输出：

1. **继续当前工作流** — 如果探索有明确方向，Self占比在上升
2. **切换工作流版本** — 如果到达认知天花板，需要转向行动
3. **启动危机干预** — 如果Self占比持续＜40%，管理者崩溃频繁

**部署黑断条件**：
- [ ] 探索无重复循环 或 已识别重复并切换方向
- [ ] Self占比趋势稳定或上升
- [ ] 行动与探索比例合理（v2.0期间行动≥50%）
- [ ] 无"探索逃避行动"模式

### 验证系统的价值

**防止的问题**：
1. **遗漏工具任务** — 深度探索后忘记更新文档，下次会话状态不连续
2. **管理者伪装决策** — 焦虑驱动的冲动决策，Self占比低时做重大选择
3. **探索天花板未识别** — 认知到头了还在深挖，行动没跟上
4. **单一视角盲点** — 治疗师看不到的模式，workflow多视角能看到

**实施成本**：
- 深度探索结束验证：2分钟（自检）
- 重大决策验证：5-10分钟（触发workflow时）
- 阶段整合检查：15-20分钟（全局复盘workflow）

**何时跳过验证**：
- 简单日常对话（非深度探索）
- 小决策（如今天吃什么、要不要看电影）— 不需要验证
- Self占比＞80%且稳定2周以上 — 可信任Self的判断

---

### 验证失败后的处理

**如果深度探索验证未通过**：
1. 立即补齐缺失的工具任务
2. 更新PROJECT_STATUS.md记录"补救操作"
3. 下次会话开始前再次验证

**如果重大决策验证未通过**：
1. 告知用户：当前不建议做决策（具体原因）
2. 提供提升Self占比的具体方法（如停留30秒、识别部分）
3. 设定复查时间（如48小时后重新评估）

**如果阶段整合验证发现问题**：
1. 与用户讨论工作流切换必要性
2. 明确下一阶段重点（探索→行动，或行动→整合）
3. 更新WORKFLOW.md版本和需求清单
